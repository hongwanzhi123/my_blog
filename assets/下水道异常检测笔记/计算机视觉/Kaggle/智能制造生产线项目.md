# 智能制造生产线视觉检测项目

智能制造生产线视觉检测通常用于替代或辅助人工质检，核心目标是在稳定节拍下完成目标定位、缺陷识别、状态判断和结果追溯。该类项目不是单纯训练一个模型，而是由数据采集、标注规范、模型选择、推理部署、异常处理和业务闭环共同组成。

## 一、任务定义

生产线视觉任务需要先明确检测对象、判定标准和输出形式。

常见任务包括：

- 产品是否存在：判断工位上是否有物料、是否漏装。
- 位置是否正确：判断零件摆放角度、安装位置、装配顺序是否符合要求。
- 外观是否异常：检测划痕、脏污、破损、缺角、变形、色差等缺陷。
- 数量是否正确：统计螺丝、焊点、孔洞、标签等关键区域数量。
- 字符是否可读：识别条码、二维码、批次号、OCR 字符。

从算法角度看，任务可以拆成分类、目标检测、语义分割、实例分割、关键点检测和 OCR 等子问题。

## 二、数据采集与标注

智能制造场景的数据质量通常比模型结构更关键。由于工业缺陷往往尺寸小、样本少、类别不均衡，采集阶段需要尽量保证光照、角度、焦距、曝光和背景稳定。

数据采集时需要关注：

- 正常样本和异常样本比例，避免只有少量缺陷样本。
- 不同批次、不同光照、不同相机位置下的数据覆盖。
- 缺陷边界是否清晰，是否需要分割级标注。
- 标注规则是否统一，例如缺陷框是否贴边、重叠缺陷是否拆分。
- 训练集、验证集和测试集是否按批次或时间合理划分。

如果异常样本很少，可以采用数据增强、合成缺陷、迁移学习、少样本学习或异常检测方法提升泛化能力。

## 三、算法方案选择

算法选择取决于输出需求和实时性要求。

分类模型适合判断整张图是否合格，例如产品外观是否异常。优点是训练简单、推理快，缺点是缺陷定位能力弱。

目标检测模型适合定位明确的缺陷或零件，例如螺丝漏装、焊点缺失、表面划痕位置。YOLO 系列适合实时场景，Faster R-CNN 更偏向高精度但速度较慢，RT-DETR 适合需要端到端检测且希望减少 NMS 依赖的场景。

语义分割和实例分割适合边界要求较高的缺陷，例如裂纹、污渍、破损边缘、区域污染。U-Net、DeepLab、Mask R-CNN、Mask2Former 等模型可用于像素级定位。

异常检测适合缺陷样本极少的场景。常见思路是学习正常样本分布，当测试图像与正常分布差异较大时判为异常。该类方法适合“正常样本容易采集，异常类型难以穷举”的工业场景。

## 四、训练流程

训练流程通常包括数据检查、样本划分、模型训练、验证评估和误差分析。

基础流程如下：

1. 检查图像是否损坏、标签是否缺失、类别编号是否一致。
2. 按产品批次、采集时间或设备编号划分训练集和验证集，避免数据泄漏。
3. 选择合适输入分辨率，小缺陷通常需要更高分辨率。
4. 使用预训练模型进行迁移学习，提高收敛速度。
5. 根据验证集结果分析漏检、误检和定位偏差。
6. 对困难样本进行补采、重标或增强。

评估指标需要结合业务目标。检测任务常用 Precision、Recall、mAP；分割任务常用 IoU、Dice；工业质检中还需要重点关注漏检率，因为漏检通常比误检风险更高。

## 五、工程部署

生产线部署关注稳定性、速度和可维护性。模型训练效果好并不代表能够直接上线，还需要处理相机取流、图像预处理、模型推理、结果后处理、PLC 或 MES 通信、日志记录和异常兜底。

部署链路一般包括：

- 相机采集：触发拍照、曝光控制、图像缓存。
- 图像预处理：裁剪 ROI、resize、归一化、颜色空间转换。
- 模型推理：使用 PyTorch、ONNX Runtime、TensorRT 等推理框架。
- 后处理：置信度过滤、NMS、mask 阈值化、面积过滤、连通域分析。
- 结果输出：合格/不合格、缺陷类别、位置坐标、可视化图像。
- 数据回流：保存误检、漏检和低置信度样本，支持后续迭代。

如果部署在边缘设备上，需要进一步考虑模型压缩、量化、剪枝、蒸馏和 batch size 设置。

## 六、常见问题

小缺陷漏检通常与输入分辨率、标注质量、样本数量和特征表达能力有关。解决方式包括提高输入分辨率、增加小目标增强、优化 anchor 或检测头、使用更强 backbone、补充困难样本。

误检较多通常与背景干扰、类别边界模糊、阈值设置不合理有关。解决方式包括加入负样本、提高置信度阈值、增加后处理规则、使用 ROI 限制检测区域。

线上效果低于离线验证通常与数据分布变化有关，例如光照变化、镜头偏移、产品批次差异、现场污染、相机参数改变。工业项目需要建立数据回流机制，持续补充真实场景样本。

## 七、知识总结

智能制造生产线视觉检测的核心不只是模型精度，而是数据、算法和工程流程的整体稳定性。数据阶段决定模型能否学到真实缺陷规律，算法阶段决定检测和定位能力，部署阶段决定系统能否在固定节拍下长期稳定运行。

该类项目的关键思路是：先明确业务判定标准，再选择合适视觉任务形式；先保证数据和标注可靠，再训练模型；先建立可运行的推理闭环，再通过误差分析持续迭代。
