# 视频增强

视频增强 = 单帧图像恢复能力 + 多帧时序信息利用能力 + 运动对齐能力 + 时序一致性控制能力。

要重点掌握这几类任务：

1. 视频超分辨率 Video Super-Resolution, VSR
2. 视频去噪 Video Denoising
3. 视频去模糊 Video Deblurring
4. 压缩视频增强 Compressed Video Enhancement
5. 低照度视频增强 Low-light Video Enhancement
6. 视频插帧 Video Frame Interpolation

## 一、视频增强和图像增强最大的区别

图像增强只处理单张图：

输入：一张低质量图像
输出：一张高质量图像

视频增强处理的是连续帧：

输入：多帧低质量视频帧
输出：多帧高质量视频帧

视频任务比图像任务多了一个核心问题：

相邻帧之间有运动，同一个物体在不同帧的位置不一样。

所以视频增强不是简单把每一帧丢进图像增强模型，而是要利用：

前后帧互补信息
时序连续性
运动对齐
长程传播
跨帧融合

例如视频超分中，某一帧模糊或细节缺失，前后帧可能刚好有清晰纹理；模型要把这些信息对齐后融合。BasicVSR++ 论文也把 VSR 的挑战概括为需要从相互错位的视频帧中收集互补信息，并提出增强传播和对齐来更有效利用时空信息。

## 二、必须掌握的核心概念
### 1. 退化模型 Degradation

视频增强首先要知道低质量视频是怎么来的。

常见退化包括：

低分辨率：downsample
噪声：Gaussian noise / Poisson noise / sensor noise
模糊：motion blur / defocus blur
压缩伪影：H.264 / H.265 / JPEG artifact
低照度：under-exposure, low SNR
混合退化：blur + noise + compression + low resolution

训练时经常用人工退化构造数据：

高质量视频
↓
下采样
↓
加噪声
↓
加模糊
↓
加压缩
↓
得到低质量视频

真实场景更复杂，因为真实视频往往是多种退化叠加的，这也是 RealBasicVSR 这类真实视频超分方法关注的问题。RealBasicVSR 论文指出，真实世界视频退化具有多样性和复杂性，严重退化会在传播过程中被放大，因此引入了 image pre-cleaning 阶段来先抑制噪声和伪影。

### 2. 时序信息 Temporal Information

视频增强的优势来自多帧信息。

例如：

当前帧看不清的纹理
可能在前一帧或后一帧更清楚

所以模型要利用：

t-2, t-1, t, t+1, t+2

这样的邻近帧。

常见输入形式：

滑动窗口：连续 5 帧 / 7 帧 / 15 帧
递归传播：从过去帧持续传播隐藏特征
双向传播：同时利用过去和未来帧
长程建模：Transformer 或 recurrent 结构建模更长时序
### 3. 运动对齐 Motion Alignment

因为视频中物体会运动，所以不能直接把前后帧相加。

要先对齐：

前一帧的物体位置
↓
对齐到当前帧
↓
再融合

常见对齐方法有：

光流 Optical Flow
可变形卷积 Deformable Convolution
特征级对齐 Feature Alignment
注意力对齐 Attention Alignment
隐式对齐 Implicit Alignment

EDVR 的核心就是 PCD alignment，即 Pyramid, Cascading and Deformable alignment，用可变形卷积在特征层做 coarse-to-fine 对齐；同时还用 TSA fusion 做时空注意力融合。

### 4. 特征传播 Feature Propagation

视频模型通常不是只看固定窗口，还会把信息沿时间传播。

例如 BasicVSR 的思路：

前向传播：从第 1 帧传到第 T 帧
后向传播：从第 T 帧传回第 1 帧
融合双向特征
重建高质量帧

BasicVSR++ 在这个基础上进一步提出：

second-order grid propagation
flow-guided deformable alignment

用更强的传播和对齐机制提升时空信息利用

## 三、视频超分辨率 VSR 需要掌握什么？
### 1. VSR 任务定义

视频超分辨率是：

输入：低分辨率视频帧 LR
输出：高分辨率视频帧 HR

常见倍率：

×2
×3
×4

数学上可以理解为：

给定 LR_{t-k}, ..., LR_t, ..., LR_{t+k}
预测 HR_t

或者预测整个 HR 序列。

### 2. VSR 的核心难点


3. 多帧之间存在运动，需要对齐
4. 低分辨率帧本身细节缺失，需要从多帧中补充
5. 对齐不准会产生重影 ghosting
6. 过强生成会产生假纹理 hallucination
7. 相邻输出帧要时序稳定，不能闪烁 flickering
8. 真实视频中常有噪声、压缩、模糊混合退化

### 3. VSR 模型路线
传统单帧路线

只把每一帧当作图片做超分：

LR_t
↓
Image SR model
↓
HR_t

优点：

简单
不会引入跨帧对齐错误

缺点：

没有利用时序信息
细节恢复有限
输出容易缺少时间一致性
多帧滑动窗口路线

输入连续几帧：

LR_{t-2}, LR_{t-1}, LR_t, LR_{t+1}, LR_{t+2}
↓
对齐
↓
融合
↓
重建 HR_t

代表思想：

EDVR

EDVR 是很经典的视频恢复框架，可以用于视频超分和去模糊，其核心是 PCD 对齐和 TSA 融合。

递归传播路线

不是只看固定窗口，而是沿时间传播特征：

frame 1 → frame 2 → frame 3 → ... → frame T

代表模型：

BasicVSR
BasicVSR++
RealBasicVSR

BasicVSR 使用双向传播和特征对齐来利用整个视频序列信息；BasicVSR++ 进一步通过二阶网格传播和 flow-guided deformable alignment 提升效果。

Transformer 路线

Transformer 用注意力机制建模长程时序关系。

代表模型：

VRT
RVRT
Video SwinIR 类方法

VRT 提出 Video Restoration Transformer，使用 temporal mutual self-attention 和 parallel warping 来建模长程时序依赖，并在视频超分、视频去模糊、视频去噪、视频插帧等多个任务上验证效果。

RVRT 则尝试结合 recurrent 和 transformer 的优点，把视频划分成多个 clip，在全局递归框架内并行处理局部邻近帧，以平衡效果和效率。

4. VSR 面试必须会讲的模型

你至少要会讲这几个：

EDVR
BasicVSR
BasicVSR++
RealBasicVSR
VRT / RVRT

面试回答可以这样组织：

视频超分的关键是跨帧信息利用。早期方法常用滑动窗口结构，例如 EDVR，它通过 PCD 可变形卷积对齐多帧特征，再用 TSA 注意力融合；后来的 BasicVSR 采用双向递归传播，把整个视频序列的信息前后传播；BasicVSR++ 在此基础上增强传播和对齐，提出二阶网格传播和 flow-guided deformable alignment；对于真实视频退化，RealBasicVSR 在传播前加入清理模块，防止噪声和压缩伪影在时序传播中被放大；Transformer 类方法如 VRT/RVRT 则通过时序注意力建模更长程依赖。

## 四、视频去噪需要掌握什么？
### 1. 视频去噪任务定义

视频去噪是：

输入：带噪声视频
输出：干净视频

常见噪声：

Gaussian noise
Poisson noise
shot noise
read noise
low-light noise
compression noise
real sensor noise
### 2. 视频去噪和图像去噪的区别

图像去噪只看一张图。

视频去噪可以利用多帧：

同一个物体在多帧中都有出现
噪声通常是随机的
真实结构在时间上更稳定

所以多帧平均理论上可以降低噪声。

但是问题是：

物体运动会导致不对齐
直接平均会产生拖影

所以视频去噪也需要：

运动补偿
多帧融合
时序一致性控制
### 3. 视频去噪常见方法
传统方法
V-BM4D
Non-local means
Patch matching
Temporal averaging

传统方法强调 patch 相似性和时空非局部匹配。

深度学习方法

代表模型：

DVDnet
FastDVDnet
RViDeNet
VRT/RVRT denoising

FastDVDnet 是一个经典实时深度视频去噪方法，它不依赖显式光流估计，强调较低计算量和较快推理速度，并且能用单个模型处理较宽范围噪声水平。

### 4. 视频去噪面试重点

1. 为什么视频去噪可以利用多帧？
2. 为什么直接多帧平均不行？
3. 运动补偿在去噪中有什么作用？
4. 噪声模型有哪些？
5. 合成噪声和真实噪声有什么区别？
6. 为什么低照度视频去噪更难？
7. 怎么评估去噪效果？

面试回答可以这样说：

视频去噪的关键是利用时域冗余。相邻帧中真实结构通常具有连续性，而噪声具有随机性，因此多帧信息可以帮助抑制噪声。但由于视频中存在相机运动和物体运动，直接平均会产生重影，所以需要对齐或隐式融合。传统方法依赖 patch matching，深度方法可以通过光流、可变形卷积、时序注意力或无光流结构进行多帧融合。FastDVDnet 这类方法不使用显式光流，而是通过网络结构学习多帧去噪，在速度和效果之间取得平衡。

## 五、视频去模糊需要掌握什么？
### 1. 视频模糊来源

常见视频模糊有：

相机抖动导致的运动模糊
物体快速运动导致的局部模糊
失焦模糊 defocus blur
低帧率导致的动态模糊
压缩和噪声叠加导致的退化
### 2. 视频去模糊任务定义
输入：模糊视频帧序列
输出：清晰视频帧序列

关键是：

利用前后帧互补清晰信息
恢复当前帧锐利边缘和纹理

例如当前帧某个区域很糊，前一帧或后一帧可能更清楚。

### 3. 视频去模糊难点
1. 模糊核空间变化，不是整张图一个固定 kernel
2. 相机运动和物体运动混合
3. 模糊区域和清晰区域同时存在
4. 对齐困难，模糊本身会影响光流估计
5. 过度锐化会产生 ringing artifact
6. 输出视频容易时序闪烁
4. 视频去模糊常见模型路线

常见方法包括：

多帧 CNN
光流对齐 + 融合
可变形卷积对齐
encoder-decoder / U-Net
recurrent restoration
Transformer restoration

EDVR 本身就是一个统一视频恢复框架，可用于视频超分和去模糊；其项目页也说明，对于 blurry inputs，会在 PCD 对齐模块前加入 PreDeblur 模块来提高对齐准确性。

VRT 也把视频去模糊作为其验证任务之一，并通过时序注意力和并行 warping 建模跨帧信息。

## 六、三个任务之间的共同核心

视频超分、去噪、去模糊虽然目标不同，但底层共性很强。

任务	主要退化	恢复目标	关键难点
视频超分	分辨率低、细节缺失	恢复高分辨率细节	多帧对齐、细节重建
视频去噪	随机噪声、传感器噪声	抑制噪声保留纹理	去噪不能抹掉细节
视频去模糊	运动模糊、失焦模糊	恢复清晰边缘	模糊下对齐困难
压缩增强	block artifact、ringing	去伪影、保细节	压缩伪影和纹理混淆

共同技术点：

1. 多帧输入
2. 运动估计 / 特征对齐
3. 跨帧融合
4. 时序传播
5. 残差学习
6. 多尺度重建
7. 时序一致性约束

## 八、评价指标必须掌握
### 1. PSNR
Peak Signal-to-Noise Ratio

衡量恢复图像和 GT 的像素误差。

特点：

越高越好
偏向像素级准确
和人眼感知不完全一致
### 2. SSIM
Structural Similarity Index

衡量结构相似度。

特点：

越高越好
比 PSNR 更关注结构
### 3. LPIPS

感知质量指标。

特点：

越低越好
更接近人眼感知
常用于生成式增强、真实视频超分
### 4. NIQE / BRISQUE

无参考图像质量指标。

适合没有 GT 的真实视频增强。

#### 5. Temporal Consistency

视频任务特别关注：

时序一致性
闪烁 flickering
运动区域稳定性

常见评估方式：

warp error
tOF
tLPIPS
人工主观评价
视频播放观察

视频增强不能只看单帧 PSNR，还要看连续帧是否稳定，有没有闪烁、重影和纹理跳变。

## 十一、必须会答的问题
### 1. 视频超分和图像超分有什么区别？

可以回答：

图像超分只利用单帧信息，而视频超分可以利用相邻帧的互补信息来恢复细节。但视频中存在运动，同一物体在不同帧的位置不一致，所以视频超分的关键是运动对齐和跨帧融合。如果对齐不准，可能产生重影和闪烁。因此 VSR 模型通常会使用光流、可变形卷积、时序注意力或递归传播来利用多帧信息。

### 2. 为什么视频增强需要运动对齐？

可以回答：

因为相邻帧之间存在相机运动和物体运动，直接融合不同帧特征会把不同位置的内容混在一起，产生 ghosting。运动对齐的作用是把前后帧中对应当前帧同一物体或区域的特征对齐后再融合。常用方法包括光流对齐、可变形卷积对齐和注意力对齐。

### 3. 光流对齐和可变形卷积对齐有什么区别？

可以回答：

光流对齐先估计像素级运动场，然后用 warping 把邻近帧对齐到当前帧，优点是运动含义明确，缺点是光流估计错误会直接影响恢复效果。可变形卷积对齐是在特征层学习采样偏移，不需要显式输出光流，能够更灵活地对齐复杂运动和局部形变。EDVR 的 PCD alignment 就是典型的多尺度可变形卷积特征对齐。

### 4. 视频增强为什么会出现闪烁？

可以回答：

闪烁通常来自相邻帧恢复结果不一致。比如模型逐帧处理时，每一帧的纹理生成、颜色校正或噪声残留都可能不同；或者跨帧对齐不稳定，导致细节在时间上跳动。解决方式包括使用多帧输入、递归传播、时序一致性 loss、光流约束、滑动窗口融合，以及推理阶段保持时序 hidden state 稳定。

### 5. 视频去噪为什么不能简单逐帧去噪？

可以回答：

逐帧去噪没有利用视频时序冗余，容易过度平滑细节，而且相邻帧去噪结果可能不一致，造成闪烁。视频去噪可以利用多帧中相同结构的重复出现来区分真实纹理和随机噪声，但需要处理帧间运动，否则直接融合会产生拖影。

### 6. 视频去模糊为什么比图像去模糊难？

可以回答：

视频去模糊不仅要恢复单帧清晰结构，还要利用前后帧互补信息并保证时序一致。模糊本身会破坏纹理和边缘，导致运动估计和对齐更困难；同时视频中不同区域可能有不同运动模糊，属于空间变化退化，不能简单用固定模糊核处理。

输出增强后视频
↓
对比原视频和增强视频
↓
统计 PSNR / SSIM / FPS
↓
支持 ONNX / Docker 部署

## 十四、最终总结

视频增强，必须掌握这条知识链：

视频退化类型
↓
多帧输入建模
↓
运动对齐
↓
时序特征传播
↓
跨帧融合
↓
重建输出
↓
时序一致性评估
↓
工程部署

最重要的模型主线是：

EDVR：
滑动窗口 + PCD 可变形卷积对齐 + TSA 融合

BasicVSR：
双向递归传播 + 光流对齐

BasicVSR++：
二阶网格传播 + flow-guided deformable alignment

RealBasicVSR：
真实退化 + pre-cleaning + 防止伪影传播

FastDVDnet：
无显式光流的快速视频去噪

VRT / RVRT：
Transformer 建模长程时序依赖

总结可以这样说：

视频增强的核心不是单帧恢复，而是如何稳定、有效地利用多帧时序信息。关键技术包括运动对齐、时序传播、跨帧融合和时序一致性控制；典型模型从 EDVR 的可变形卷积对齐，到 BasicVSR 系列的递归传播，再到 VRT/RVRT 的 Transformer 长程建模，都是围绕如何更好利用跨帧信息来提升超分、去噪和去模糊效果。

## 十五、目前工程上真正常用的视频超分

大致分成 逐帧图像超分、时序视频超分、轻量实时超分、商业 SDK / 闭源方案 四类。实际落地时，大家不一定用论文里最新最强的模型，而是优先考虑 速度、显存、稳定性、部署难度、是否闪烁、是否支持真实退化视频。

### 1. Real-ESRGAN 系列：工程落地最常见的一类

严格来说，Real-ESRGAN 更偏 图像超分 / 图像修复模型，用于视频时通常是把视频拆帧，对每一帧单独超分，再合成视频。它的优势是部署简单、效果直观、真实低清图像适应性比传统 ESRGAN 更好，所以在动漫修复、老视频修复、短视频增强、小工具软件里非常常见。官方也明确把 Real-ESRGAN 定位为 practical algorithms for general image/video restoration，并提供 general、anime、anime video 等模型。

工程上常见模型包括：

模型	常见用途	优点	缺点
RealESRGAN_x4plus	通用真实图像/视频帧超分	效果稳，部署资料多	逐帧处理，可能闪烁
RealESRGAN_x4plus_anime_6B	动漫图片/视频帧	小、快、适合二次元	不适合真实场景
realesr-animevideov3	动漫视频	专门优化动漫视频，模型小	仍然主要是逐帧增强
realesr-general-x4v3	通用轻量增强	更快，可调降噪强度	细节生成能力弱于大模型

如果你要快速做一个视频增强 Demo，Real-ESRGAN 是最容易落地的选择：ffmpeg 拆帧 → Real-ESRGAN 推理 → ffmpeg 合成。官方文档里也给了这种视频处理流程，并且有 ncnn-vulkan 版本，适合不依赖 PyTorch 的桌面端部署。

不过它最大的问题是：没有真正利用时间信息。如果每一帧生成的纹理略有不同，视频播放时可能出现闪烁、纹理跳动。

### 2. BasicVSR / IconVSR / BasicVSR++：视频超分工程和论文里最常见的主干

如果你问的是“真正的视频超分模型”，那 BasicVSR 系列一定要掌握。BasicVSR 的核心是 双向时序传播 + 光流特征对齐，让当前帧同时利用过去帧和未来帧信息；BasicVSR++ 进一步提出 二阶网格传播 和 光流引导可变形对齐，在类似参数量下比 BasicVSR 提升明显。MMagic 文档也说明 BasicVSR++ 相比 BasicVSR 提升约 0.82 dB PSNR。

模型	常见用途	优点	工程问题
BasicVSR	视频超分 baseline	结构清晰，适合面试讲解	依赖光流，复杂运动会出错
IconVSR	BasicVSR 增强版	加入信息补充和耦合传播	比 BasicVSR 更复杂
BasicVSR++	高质量视频超分	时序传播强，对齐更准	DCN / deformable conv 部署麻烦
Light-BasicVSR++	较轻量版本	性能和速度折中	效果不如完整模型

工程上如果是 服务器离线处理，BasicVSR++ 很有吸引力；如果是 实时端侧部署，BasicVSR++ 的可变形卷积、光流、显存占用都会增加难度。BasicVSR++ 官方项目也强调，它通过 second-order grid propagation 和 flow-guided deformable alignment 改进 BasicVSR。

你面试时可以这样说：

如果只是快速做视频增强工具，Real-ESRGAN 更容易落地；如果要体现“视频算法能力”，我会选择 BasicVSR 或 BasicVSR++，因为它们真正利用了多帧时序信息，能解决逐帧超分的闪烁问题。

### 3. RealBasicVSR：真实世界视频超分更常用

BasicVSR 和 BasicVSR++ 在标准数据集上很强，但真实视频里有压缩噪声、运动模糊、抖动、过曝、欠曝、码率损伤等问题。RealBasicVSR 就是面向 real-world video super-resolution 的方法。它关注真实退化视频中的一个关键问题：长时序传播虽然有利于轻度退化，但严重退化会在传播中被放大，影响输出质量。

工程上，RealBasicVSR 比 BasicVSR 更适合以下场景：

低码率视频增强；

老视频修复；

网络压缩视频增强；

监控视频清晰化；

真实手机拍摄视频增强。

它的定位可以理解为：

BasicVSR / BasicVSR++ 更偏标准 VSR benchmark；RealBasicVSR 更偏真实退化视频工程落地。

如果你要做一个“真实视频增强项目”，RealBasicVSR 比单纯 BasicVSR 更有说服力。

### 4. EDVR：老牌但仍常见的滑动窗口视频恢复模型

EDVR 是较早非常经典的视频恢复框架，核心是 PCD 对齐 + TSA 融合。PCD 是 pyramid cascading deformable alignment，用多尺度可变形卷积做特征对齐；TSA 是 temporal-spatial attention，用于时序和空间注意力融合。官方项目页把 EDVR 定位为统一的视频恢复框架，可用于超分、去模糊等任务。

EDVR 工程上的特点是：

项目	说明
框架类型	滑动窗口式视频超分
输入方式	当前帧附近若干帧
优点	结构成熟，资料多，效果稳
缺点	长时序利用不如 BasicVSR 系列
部署难点	deformable conv 需要额外算子支持

现在很多新项目未必首选 EDVR，但它仍然是视频恢复领域很重要的 baseline。你面试时知道 EDVR，会显得你不是只了解 BasicVSR。

### 5. VRT / RVRT：高质量离线视频修复，部署成本较高

VRT 和 RVRT 属于 Transformer 视频恢复模型。VRT 使用时空注意力建模多帧依赖，RVRT 则结合 recurrent 思路和 guided deformable attention，在视频超分、去模糊、去噪任务上都有很强表现。VRT 官方说明它面向 video restoration，例如 video super-resolution；RVRT 官方说明它在视频超分、去模糊、去噪上取得 SOTA，并强调模型大小、显存和速度之间的平衡。

这类模型适合：

离线高质量修复；

影视级增强；

论文实验；

服务器批处理。

但它们不太适合普通实时部署，因为 Transformer 视频模型通常显存压力大、推理慢、工程优化复杂。尤其是长视频，需要切块、分段、缓存和边界融合。

6. 轻量单帧超分模型：移动端、实时流媒体更常用

如果是手机端、嵌入式、实时视频流，不一定能跑 BasicVSR++ 或 RVRT。很多工程会退而求其次，用轻量图像超分模型逐帧处理，例如：

模型	特点
FSRCNN	很轻，速度快，适合实时
ESPCN	PixelShuffle 经典方法，轻量
LapSRN	逐级上采样
EDSR-lite	效果比 FSRCNN/ESPCN 强，但更重
IMDN / RFDN / RLFN	轻量图像超分常见选择
SwinIR-light	效果较好，但比纯 CNN 重

OpenCV 的 dnn_superres 模块就集成了 EDSR、ESPCN、FSRCNN、LapSRN 这几类模型，因此它们在工程快速验证和轻量部署里仍然常见。

这类方法的问题还是：逐帧处理，不保证时间一致性。但如果业务更关心实时速度，比如摄像头预览、低端设备视频增强，它们反而比大模型更现实。

7. NVIDIA Maxine / 商业 SDK：真正产品化时也很常见

在会议、直播、实时视频增强场景里，很多公司不会从论文模型开始自己训练，而是直接用商业 SDK 或闭源模型。例如 NVIDIA Maxine Video Effects SDK 提供 Video Super Resolution，官方说明它是 AI-powered upscaling，除了提升分辨率，还支持 denoise 和 deblur 模式，并面向实时视频增强。

这种方案的特点是：

优点	缺点
工程成熟、实时性好	模型细节不可控
和 NVIDIA GPU 生态结合好	依赖特定硬件和 SDK
适合会议、直播、视频处理软件	不适合作为论文创新点

如果你的目标是求职面试，可以知道这类方案，但项目里最好还是讲开源模型，比如 Real-ESRGAN、BasicVSR++、RealBasicVSR。

按场景推荐
场景	推荐模型
快速做视频增强 Demo	Real-ESRGAN / realesr-general-x4v3
动漫视频超分	realesr-animevideov3 / RealESRGAN anime
真实低清视频修复	RealBasicVSR / Real-ESRGAN
想体现视频时序建模能力	BasicVSR / BasicVSR++
追求高质量离线修复	BasicVSR++ / RVRT / VRT
老牌视频恢复 baseline	EDVR
移动端 / 实时低延迟	FSRCNN / ESPCN / RFDN / IMDN / EDSR-lite
商业实时视频增强	NVIDIA Maxine VSR
最实际的工程选择

如果你现在要做一个面试项目，我建议这样选：

第一版：Real-ESRGAN
最快落地，能做出明显前后对比，有视频输出，工程完整。

第二版：BasicVSR++ 或 RealBasicVSR
体现你理解视频超分中的多帧对齐、时序传播、光流、时间一致性。

第三版：部署优化
把模型转 ONNX / TensorRT / ncnn，加入视频拆帧、批处理、tile 推理、音视频合成、显存控制。

面试里你可以这样总结：

工程落地中，最常见的是 Real-ESRGAN 这类逐帧真实超分模型，因为部署简单、效果直观；如果要真正利用视频时序信息，常用 BasicVSR、BasicVSR++、RealBasicVSR、EDVR 这类视频恢复模型；如果追求离线高质量，可以考虑 VRT/RVRT；如果是移动端或实时业务，通常会选择 FSRCNN、ESPCN、RFDN、EDSR-lite 这类轻量模型，或者直接使用 NVIDIA Maxine 等商业 SDK。

## 十六、目前工程上常用的视频去噪

按场景分成几类：传统滤波 / 编码器级降噪、轻量深度视频去噪、真实 RAW 视频去噪、高质量离线 Transformer 去噪、商业 SDK 方案。

如果你是为了面试视频增强方向，重点掌握这几个名字：FastDVDnet、EMVD、BSVD、RVRT / VRT、RViDeNet / RViDeformer、OpenCV / FFmpeg 传统降噪、NVIDIA Maxine 这类商业实时方案。

### 1. 传统工程方案：FFmpeg / OpenCV 降噪

这一类不是最先进，但工程上非常常见，原因是：稳定、快、无训练成本、容易部署、不会生成假细节。

常见方法有：

方法	常见工具	特点
hqdn3d	FFmpeg	空间 + 时间 3D 降噪，适合压缩前预处理、老视频降噪
nlmeans	FFmpeg / OpenCV	非局部均值，保边能力比简单模糊好，但速度慢
fastNlMeansDenoisingMulti	OpenCV	利用连续多帧做非局部均值降噪
BM3D / VBM4D	学术/离线工具	经典块匹配去噪，效果稳但速度较慢

FFmpeg 的 hqdn3d 是很典型的工程滤波器，官方说明它是 high quality 3D denoise filter，用于减少噪声、让静态区域更稳定，并提升压缩效率。 OpenCV 里也有 fastNlMeansDenoisingMulti，它是针对图像序列/视频帧的非局部均值去噪函数，利用连续帧信息提升去噪效果。

这类方法适合：

老视频预处理；

视频压缩前降噪；

监控视频轻量增强；

没有 GPU 的场景；

对内容真实性要求高、不希望 AI 生成假纹理的场景。

缺点也明显：强降噪容易糊，复杂运动下时间滤波容易拖影，低光照重噪声效果有限。

### 2. FastDVDnet / DVDnet：深度视频去噪里的经典实用模型

FastDVDnet 是非常经典的视频去噪网络。它的官方仓库介绍为 “very fast deep video denoising”，并且强调 不使用显式运动补偿。

它的核心思路是：

输入多帧 noisy video
        ↓
不用显式光流对齐
        ↓
通过 CNN 从邻近帧中学习时空信息
        ↓
输出中心帧 / 多帧去噪结果

FastDVDnet 的工程价值在于：

第一，结构相对简单，容易跑通；

第二，不依赖光流，所以没有光流估计错误带来的额外复杂度；

第三，速度较快，适合做视频去噪 baseline；

第四，对合成高斯噪声、普通 sRGB 视频去噪比较常用。

但是它也有局限：真实视频噪声往往不是简单高斯噪声，而是包含压缩噪声、ISP 处理痕迹、低光照彩噪、运动模糊等复杂退化。FastDVDnet 在真实低光视频上不一定足够稳。

面试时可以这样说：

FastDVDnet 是经典的轻量深度视频去噪模型，它不显式估计光流，而是直接从多帧输入中学习时空相关性，因此部署和训练相对简单，是工程上做视频去噪 baseline 的常见选择。

## 3. EMVD：移动端 / 低算力场景很重要

EMVD 全名是 Efficient Multi-Stage Video Denoising with Recurrent Spatio-Temporal Fusion。它是非常偏工程落地的一个方法，特点是低复杂度、低显存、适合移动端。论文摘要说明，EMVD 通过多阶段结构降低复杂度：先做 temporal fusion，再做 denoising，最后 refinement，并且低复杂度和低内存需求使它可以在商业移动 SoC 上实时运行。

它的思路可以概括成：

视频帧
  ↓
时域融合：利用历史帧降低噪声
  ↓
空间降噪：对融合帧进一步去噪
  ↓
时空精修：恢复细节和高频

EMVD 适合：

手机端视频去噪；

相机 ISP 后处理；

低光 RAW / sRGB 视频增强；

需要实时或接近实时的设备端场景。

它的优势是工程友好，不是单纯追求最高指标，而是非常重视计算量、内存和实时性。官方实现也说明 EMVD 是通过 temporal fusion、spatial denoising、spatio-temporal refinement 多级 recurrent 方式利用时空相关性。

## 4. BSVD / FloRNN：流式视频去噪

实际工程里很多视频是 实时流，比如摄像头、直播、会议、安防监控。这个时候你不能等未来很多帧都来了再处理，否则延迟太高。

这类场景常见的是 streaming video denoising，代表方法有 BSVD 和 FloRNN。

BSVD 的官方实现说明它是 “Real-time Streaming Video Denoising with Bidirectional Buffers”，目标是流式视频实时去噪。 论文摘要也说明，BSVD 通过 bidirectional buffers 在流式场景中同时利用过去和近未来信息，以实现高质量实时视频去噪。

它解决的问题是：

离线模型：
可以看完整视频，效果好，但延迟高

在线模型：
只能看过去帧，延迟低，但信息不足

BSVD：
用缓冲区拿到有限未来帧，在延迟和效果之间折中

FloRNN 则是另一个循环视频去噪方向的方法，官方仓库描述为 “Unidirectional Video Denoising by Mimicking Backward Recurrent Modules with Look-ahead Forward Ones”。 它的思路是用 look-ahead 模块模拟反向循环信息，让单向在线处理也能利用近未来信息。

这类方法适合：

摄像头实时去噪；

直播推流；

视频会议；

边缘设备实时增强；

对延迟有明确要求的业务。

## 5. VRT / RVRT：高质量离线视频去噪

如果追求高质量、服务器离线处理，可以考虑 VRT 和 RVRT。

VRT 是 Video Restoration Transformer，官方仓库说明它具有 parallel frame prediction 和 long-range temporal dependency modelling 能力，使用 TMSA 和 parallel warping，其中 TMSA 在 clip 内通过 mutual attention 联合完成运动估计、特征对齐和融合。

RVRT 是 Recurrent Video Restoration Transformer with Guided Deformable Attention，官方仓库说明它在视频超分、视频去模糊、视频去噪任务上取得强结果，并且强调模型大小、测试显存和运行时间之间的平衡。 RVRT 论文中也明确用于视频去噪，在 DAVIS 训练，并在 DAVIS 和 Set8 上测试。

这类模型的优点是：

视频时序建模强；

细节保留好；

去噪、去模糊、超分都可以统一成视频复原；

适合高质量离线修复。

缺点是：

显存压力大；

推理速度慢；

部署复杂；

Transformer、光流、可变形注意力等模块转 ONNX / TensorRT 不一定容易。

所以工程上它们更适合：

服务器离线批处理；

影视修复；

高质量视频增强；

研究型项目；

面试项目中展示算法能力。

不太适合：

移动端实时；

低延迟视频会议；

普通 CPU-only 场景。

## 6. RViDeNet / RViDeformer：RAW 视频去噪

如果是手机相机、工业相机、低光摄像头，工程上更推荐在 RAW 域 去噪，而不是等 ISP 输出 sRGB 后再处理。因为 RAW 域的噪声模型更清楚，很多噪声还没有被 ISP 的锐化、压缩、颜色变换放大。

代表方法有：

方法	场景	特点
RViDeNet	RAW 视频去噪	CVPR 2020，基于 CRVD 数据集
EMVD	RAW / 实时去噪	轻量，适合端侧
RViDeformer	RAW 视频 Transformer 去噪	利用短距离和长距离相关性
Real-LLRVD 系列	真实低光 RAW 视频	面向复杂低光真实噪声

RViDeNet 官方仓库说明它是 “Supervised Raw Video Denoising with a Benchmark Dataset on Dynamic Scenes”，是 CVPR 2020 的 RAW 视频去噪方法。 CRVD 数据集包含 55 组 noisy-clean 视频，ISO 范围从 1600 到 25600，是 RAW 视频去噪里很经典的数据集。

RViDeformer 则是更新一些的 RAW 视频 Transformer 方法，它提出高效 RAW 视频去噪 Transformer，并构建 ReCRVD 数据集；论文摘要说明它通过多分支时空注意力探索局部窗口、低分辨率窗口、全局下采样窗口和邻帧窗口相关性，并使用重参数化降低计算成本。 官方实现也说明 RViDeformer 是 TCSVT 2025 的 Efficient Raw Video Denoising Transformer。

工程上，如果你做的是：

手机夜景视频；

安防低照度摄像头；

工业相机低光视频；

RAW pipeline；

那 RAW 视频去噪比直接 sRGB 去噪更专业。

## 7. 无监督 / 自监督视频去噪：没有干净 GT 时使用

很多真实场景没有 clean ground truth，比如显微视频、医学视频、监控视频、低光真实拍摄视频。这时监督学习很难做，可以考虑无监督或自监督视频去噪。

代表方法有：

方法	思路
UDVD	无监督深度视频去噪
Noise2Void / Noise2Self 扩展到视频	用 blind-spot 约束避免学成 identity
Self-supervised optical-flow aligned denoising	用相邻帧对齐后构造监督
TAP / temporal plugin 类方法	把时间模块接到预训练图像去噪器上

UDVD 官方页面说明，它面向没有 noiseless videos 的应用，例如 microscopy，基于无监督静态图像去噪发展出 Unsupervised Deep Video Denoiser。

自监督方法适合：

没有干净标签；

真实噪声难模拟；

特定设备 / 特定场景；

需要在线适配某类视频。

缺点是训练和调参更麻烦，效果通常依赖噪声假设，稳定性不如有监督模型。

## 8. 商业实时方案：NVIDIA Maxine 等 SDK

如果是视频会议、直播、美颜、摄像头增强，很多公司不会自己训练完整模型，而是直接用 SDK。

NVIDIA Maxine Video Effects SDK 里就有 Webcam Denoising。官方文档说明它可以去除 webcam video 中的噪声，同时保留纹理细节，并且提供强度参数。 Maxine VFX SDK 总览也列出 Webcam Denoising，说明其作用是去除摄像头视频噪声并保留纹理细节。

这类方案适合：

视频会议；

直播推流；

实时摄像头增强；

NVIDIA GPU 环境；

产品快速集成。

缺点是模型不可控、依赖 SDK 和硬件，不适合作为论文创新点，但非常符合工程产品落地。

## 按实际场景怎么选
场景	推荐方法
快速工程预处理	FFmpeg hqdn3d / nlmeans
OpenCV 小项目	fastNlMeansDenoisingMulti
深度学习 baseline	FastDVDnet
移动端 / 低算力	EMVD
实时流式视频	BSVD / FloRNN
高质量离线去噪	RVRT / VRT
RAW 低光视频	RViDeNet / EMVD / RViDeformer
没有 clean GT	UDVD / self-supervised video denoising
视频会议 / 商业实时	NVIDIA Maxine Webcam Denoising
面试里可以这样总结

视频去噪工程上主要分三条路线。

第一条是传统滤波路线，比如 FFmpeg 的 hqdn3d、nlmeans 和 OpenCV 的 fastNlMeansDenoisingMulti，优点是稳定、简单、部署成本低，适合预处理和无 GPU 场景。

第二条是深度视频去噪路线，比如 FastDVDnet、EMVD、BSVD、RVRT。FastDVDnet 结构简单、不依赖显式光流，适合做 baseline；EMVD 面向低算力和端侧实时；BSVD 适合流式视频；RVRT / VRT 更适合高质量离线处理。

第三条是 RAW 视频去噪路线，比如 RViDeNet、RViDeformer、EMVD。它们更适合手机相机、低光摄像头和工业相机，因为 RAW 域噪声模型更明确，去噪效果通常比 sRGB 后处理更可控。

最核心的一句话是：

工程上做视频去噪，要先判断是实时还是离线、sRGB 还是 RAW、有没有干净 GT、是否允许延迟；实时端侧优先 EMVD / BSVD / SDK，高质量离线优先 RVRT / VRT，快速落地优先 FastDVDnet 或 FFmpeg / OpenCV。

## 十七、目前工程上常用的视频去模糊模型算法

目前工程上常用的视频去模糊方法，可以分成 6 类：

传统反卷积 / 锐化类方法
逐帧图像去模糊模型
滑动窗口式视频去模糊模型
循环传播式视频去模糊模型
Transformer 视频复原模型
商业 SDK / 成品软件方案

如果你是为了面试视频增强方向，重点掌握这些名字：EDVR、STFAN、CDVD-TSP、ESTRNN、VRT、RVRT、MPRNet、Restormer、NAFNet、DeblurGAN-v2。工程产品里还会见到 Topaz Video Themis 和 NVIDIA Maxine Deblur 这类商业方案。

### 1. 传统方法：反卷积、锐化、稳定化后处理

传统视频去模糊一般基于模糊模型：

模糊图像 = 清晰图像 * 模糊核 + 噪声

其中 * 表示卷积，模糊核可以理解成运动轨迹，比如相机抖动造成的斜线核、水平运动核、旋转核等。

常见传统方法包括：

方法	作用	优点	缺点
Wiener deconvolution	已知或估计模糊核后做反卷积	快、简单	对噪声敏感
Richardson-Lucy	迭代反卷积	细节恢复较强	容易振铃、放大噪声
Blind deconvolution	同时估计模糊核和清晰图	不需要已知核	不稳定，参数敏感
Unsharp Mask / Sharpen	视觉锐化	快、工程常用	不是真正去模糊
稳定化 + 去模糊	先减少抖动，再增强清晰度	适合手持视频	无法恢复严重运动模糊

工程上，传统方法现在很少作为高质量主方案，但仍常用于：

老视频预处理；

相机 ISP 中的轻量锐化；

低算力设备；

深度模型前后的辅助处理；

视频压缩前增强。

它们最大的问题是：容易把噪声、压缩块、振铃伪影一起放大。所以在真实低质量视频里，传统锐化经常看起来“更清楚”，但其实只是边缘更硬，不一定恢复了真实细节。

### 2. 逐帧图像去模糊模型：MPRNet、Restormer、NAFNet、DeblurGAN-v2

很多工程里，如果没有条件跑真正的视频模型，会先用 图像去模糊模型逐帧处理视频。

也就是：

第 1 帧 → 图像去模糊模型
第 2 帧 → 图像去模糊模型
第 3 帧 → 图像去模糊模型
...

这种方法部署简单，特别适合快速 demo。

2.1 DeblurGAN-v2

DeblurGAN-v2 是早期比较实用的 GAN 去模糊模型，特点是速度快、视觉锐化明显。它使用 relativistic conditional GAN、double-scale discriminator，并把 FPN 引入生成器结构。官方仓库也强调 DeblurGAN-v2 面向单图运动去模糊，提升了效率、质量和灵活性。

它适合：

实时性要求较高；

希望结果主观看起来更锐；

不太追求像素级真实还原。

缺点是：

可能生成假纹理；

对文字、车牌、精细图案不一定可靠；

逐帧处理视频时可能闪烁。

2.2 MPRNet

MPRNet 是 CVPR 2021 的多阶段图像复原网络，支持去雨、去模糊、去噪等任务。它采用 multi-stage progressive restoration 思路，把复杂复原任务拆成多个阶段逐步恢复，并通过跨阶段信息交互减少信息损失。官方仓库也说明 MPRNet 在图像去雨、去模糊、去噪等多个数据集上表现强。

工程上，MPRNet 适合：

单图去模糊 baseline；

视频逐帧增强；

对恢复质量有一定要求，但不想上很复杂视频模型。

缺点是：

逐帧处理没有时间一致性；

模型相比轻量 CNN 仍然偏重；

视频中可能出现帧间纹理跳动。

2.3 Restormer

Restormer 是 CVPR 2022 Oral 的高分辨率图像复原 Transformer，支持单图运动去模糊、离焦去模糊、去雨、去噪等任务。官方仓库明确列出了 single-image motion deblurring、defocus deblurring、Gaussian/real denoising 等任务和预训练模型。

它的特点是：

Transformer 表达能力强；

高分辨率图像恢复效果好；

适合离线高质量图像去模糊。

缺点是：

视频逐帧使用时仍然可能闪烁；

显存比普通 CNN 更高；

实时部署不友好。

2.4 NAFNet

NAFNet 是一个非常值得你记的工程型图像复原模型。它的核心思想是：复杂非线性激活不一定必要，很多模块可以用乘法门控或更简单结构替代。官方仓库显示，NAFNet 在 GoPro 图像去模糊 benchmark 上达到很强结果，同时计算量比之前方法低很多。

工程上，NAFNet 很适合：

图像去模糊；

逐帧视频去模糊；

作为轻量高质量 baseline；

ONNX / TensorRT 部署前的候选模型。

如果你面试时想讲“工程落地”，NAFNet 比一些很重的 Transformer 更有说服力。

逐帧模型的核心问题

逐帧模型虽然方便，但视频里会有一个大问题：

每一帧单独恢复
    ↓
每帧生成的纹理略有不同
    ↓
播放时出现闪烁、跳纹理、边缘抖动

所以逐帧方法适合快速落地，但如果面试官问“你怎么保证视频时间一致性”，你需要回答：

可以加入光流一致性损失；

可以做时序平滑；

可以用视频模型替代逐帧模型；

可以用 RVRT / VRT / EDVR 这类多帧模型。

### 3. EDVR：经典滑动窗口式视频去模糊

EDVR 是视频复原领域非常经典的方法，全名是 Enhanced Deformable Video Restoration。它是一个统一视频复原框架，可以用于视频超分和视频去模糊。EDVR 的核心模块是 PCD Alignment 和 TSA Fusion，即金字塔级联可变形对齐和时空注意力融合。官方项目页也明确说明 EDVR 适用于视频超分和去模糊，模糊输入时会加入 PreDeblur 模块来改善后续对齐。

EDVR 的整体流程是：

输入中心帧附近多帧
        ↓
特征提取
        ↓
PreDeblur 模块
        ↓
PCD Alignment：把邻近帧对齐到中心帧
        ↓
TSA Fusion：时间 + 空间注意力融合
        ↓
重建中心帧
EDVR 为什么适合视频去模糊？

视频去模糊通常需要利用邻近帧，因为当前帧模糊的细节，可能在前后帧里更清楚。EDVR 的 PCD 模块通过金字塔和可变形卷积处理大运动和局部错位；TSA 模块判断哪些帧、哪些区域更可靠，从而避免错误帧污染结果。EDVR 论文也指出，视频复原的挑战在于大运动对齐和不同帧之间的有效融合。

它适合：

离线视频去模糊；

视频超分 + 去模糊统一任务；

较短窗口多帧恢复；

想展示 PCD / TSA 这类经典模块的项目。

缺点是：

滑动窗口只能利用局部时间范围；

DCN / 可变形卷积部署麻烦；

显存和算力需求不低；

长视频处理需要滑窗，容易有边界处理问题。

面试一句话：

EDVR 的本质是：用 PCD 把邻近帧特征对齐到中心帧，再用 TSA 选择有用的时间和空间信息，最后恢复清晰中心帧。

### 4. STFAN：把对齐和去模糊统一到动态滤波里

STFAN 全名是 Spatio-Temporal Filter Adaptive Network for Video Deblurring，是 ICCV 2019 的视频去模糊方法。它的核心思想是：对齐和去模糊本质上都是空间位置变化的操作，可以用输入自适应生成的滤波器统一处理。官方项目页说明，STFAN 通过 Filter Adaptive Convolutional Layer 同时处理帧间对齐和去模糊。

它的输入通常包括：

上一帧模糊图像
上一帧已恢复图像
当前帧模糊图像

然后网络动态生成滤波器，用来：

对齐上一帧恢复特征；
去除当前帧的空间变化模糊。

传统方法一般是：

先光流对齐
再图像去模糊

STFAN 则更像：

动态滤波器同时做对齐和去模糊

它适合你理解一个重要思想：

视频去模糊不一定必须显式估计光流，也可以通过动态卷积 / 自适应滤波隐式完成对齐和复原。

缺点是：

方法相对早期；

效果和泛化能力不一定比新 Transformer / RVRT 强；

工程使用热度不如 EDVR / RVRT。

### 5. CDVD-TSP：级联视频去模糊 + 时间锐度先验

CDVD-TSP 全名是 Cascaded Deep Video Deblurring Using Temporal Sharpness Prior，CVPR 2020。官方仓库说明它是该论文的官方实现。

它的核心思想是：

视频中并不是每一帧都同样模糊，附近可能存在相对更清晰的帧。模型可以利用这些“时间上的清晰信息”帮助恢复当前模糊帧。

CDVD-TSP 的流程大致是：

模糊视频帧
        ↓
估计中间潜在清晰帧
        ↓
从潜在清晰帧中估计光流
        ↓
根据光流聚合时间信息
        ↓
级联式逐步恢复清晰结果

项目页也说明，CDVD-TSP 主要由从 intermediate latent frames 估计 optical flow 和 latent frame restoration 两步组成。

它适合：

存在局部清晰帧的视频；

手持视频去模糊；

较强运动模糊恢复；

研究型项目对比。

缺点是：

结构复杂；

依赖估计潜在清晰帧和光流；

部署不如 NAFNet、EDVR 直观。

面试里可以这样讲：

CDVD-TSP 的关键是利用时间锐度先验，认为视频邻近帧中可能存在相对更清晰的信息，通过级联恢复和潜在帧光流估计逐步去模糊。

### 6. ESTRNN：高效循环视频去模糊

ESTRNN 全名是 Efficient Spatio-Temporal Recurrent Neural Network for Video Deblurring。它是偏工程效率的视频去模糊模型，目标是实时或低成本视频去模糊。官方仓库说明该工作提出了一个高效 RNN-based model，并构建了真实世界视频去模糊数据集 BSD。

它解决的问题是：

视频去模糊需要时序信息
但滑动窗口方法计算重复、效率低
所以使用循环网络传递历史信息

ESTRNN 的基本思路是：

当前模糊帧
    +
历史隐藏特征
        ↓
RNN Cell 提取空间特征和时序信息
        ↓
输出当前清晰帧
        ↓
隐藏特征传给下一帧

它还引入了全局时空注意力，用于融合过去和未来帧中的有效层级特征。论文摘要指出，ESTRNN 使用 residual dense blocks 改进 RNN cell 以提高空间特征提取效率，并提出 global spatio-temporal attention 来融合过去和未来帧的有效特征。

ESTRNN 适合：

实时视频去模糊；

长视频处理；

算力有限但需要利用时序信息；

工程 demo 中体现“循环传播”。

优点：

比纯 Transformer 轻；

比逐帧模型时间一致性好；

比滑动窗口重复计算少。

缺点：

隐藏状态传播可能累积误差；

极端大运动和强遮挡仍然困难；

效果上限通常不如 RVRT / VRT 这类高质量离线模型。

面试一句话：

ESTRNN 的本质是：用 RNN 在视频时间轴上传递历史复原信息，用轻量时空模块在保证效率的同时完成连续帧去模糊。

### 7. VRT：高质量 Transformer 视频去模糊

VRT 是 Video Restoration Transformer，不是只做超分，也覆盖视频去模糊、去噪、插帧等任务。官方仓库说明 VRT 具有 parallel frame prediction 和 long-range temporal dependency modelling 能力；其 TMSA 模块在 clip 内通过 mutual attention 同时完成运动估计、特征对齐和特征融合。

VRT 的视频去模糊逻辑是：

输入一段模糊视频
        ↓
多尺度 Transformer 特征提取
        ↓
TMSA：互注意力做跨帧软对齐和融合
        ↓
Parallel Warping：补充处理大运动
        ↓
重建多个清晰帧

VRT 相比 EDVR 的不同是：

对比	EDVR	VRT
主体	CNN + DCN	Transformer
对齐	PCD 可变形卷积	Mutual Attention + Warping
输出	滑窗中心帧	并行多帧
长时序	较弱	更强
算力	中等偏高	高

VRT 官方 README 中列出，其在视频去模糊任务 GoPro、DVD、REDS 上相较已有方法有明显提升。

适合：

高质量离线视频去模糊；

研究型项目；

服务器端处理；

想展示 Transformer 视频复原能力。

不适合：

移动端实时；

显存很小的环境；

简单部署。

### 8. RVRT：目前高质量视频复原里很重要的选择

RVRT 全名是 Recurrent Video Restoration Transformer with Guided Deformable Attention。它把 VRT 的 Transformer 建模能力和 BasicVSR 这类循环传播思想结合起来。官方仓库说明 RVRT 在视频超分、视频去模糊、视频去噪任务上取得强结果，并强调模型大小、显存和运行时间之间的平衡。

RVRT 的核心是：

视频切成 clips
        ↓
clip 内：Transformer 并行融合多帧
        ↓
clip 间：recurrent 传播长期信息
        ↓
GDA：Guided Deformable Attention 做 clip-to-clip 对齐
        ↓
输出清晰视频

论文摘要也明确说，RVRT 把视频分成多个 clips，用前一个 clip 的已推理特征估计后一个 clip；clip 内帧特征联合更新，clip 间用 guided deformable attention 对齐，并在视频超分、去模糊、去噪上取得 SOTA，同时保持模型大小、显存和速度的平衡。

RVRT 比 VRT 更工程友好一些，因为它不是完全并行处理整段视频，而是 clip 内并行、clip 间循环，显存更可控。

适合：

高质量视频去模糊；

视频去噪 / 超分 / 去模糊统一项目；

服务器离线处理；

面试展示前沿模型能力。

缺点：

仍然比较复杂；

依赖光流 / deformable attention；

部署 ONNX / TensorRT 有难度；

移动端实时不现实。

面试一句话：

RVRT 的本质是：clip 内用 Transformer 做多帧并行融合，clip 间用循环传播建模长时序，再用 GDA 做跨 clip 动态对齐。

### 9. 商业方案：Topaz Video Themis、NVIDIA Maxine Deblur

实际工程产品里，很多团队不会自己训练去模糊模型，而是用商业 SDK 或软件。

9.1 Topaz Video Themis

Topaz Video AI 中的 Themis 是 Motion Deblur 专用模型。Topaz 官方文档说明，Themis 通过去除模糊来提升视频感知清晰度和细节，而不是简单增加边缘对比；它主要针对平移、旋转、缩放导致的运动模糊。

它适合：

剪辑工作流；

老视频修复；

影视素材处理；

快速获得主观可见提升。

缺点是闭源，模型不可控，不适合作为算法论文创新点。

9.2 NVIDIA Maxine Deblur

NVIDIA Maxine VFX SDK 的 Video Super Resolution filter 中提供了 Deblur 模式，包括 Deblur Low / Medium / High / Ultra 等模式。官方文档也说明 Deblur 模式下输出分辨率与输入相同，不做上采样。

它适合：

NVIDIA GPU 环境；

实时视频增强；

会议 / 直播 / 视频处理软件；

SDK 快速集成。

缺点也是闭源、依赖硬件和 SDK。

    ↓

    ↓

    ↓

这版适合 1 天内做出 demo。

第二版：EDVR 视频去模糊

如果想体现“我懂视频增强”，就不要只做逐帧。你可以接 EDVR，因为它能讲：

多帧输入；

特征对齐；

EDVR 是视频复原经典方法，很适合面试。

面试中可以这样总结

视频去模糊工程上主要有三条路线。

第一条是 逐帧图像去模糊，比如 MPRNet、Restormer、NAFNet、DeblurGAN-v2。它们部署简单，适合快速 demo，但缺点是没有显式时间一致性，视频播放时可能闪烁。

第二条是 多帧视频去模糊，比如 EDVR、STFAN、CDVD-TSP、ESTRNN。它们会利用相邻帧信息，通过光流、可变形卷积、动态滤波或循环传播完成帧间对齐和融合，时间一致性更好。

第三条是 Transformer 视频复原，比如 VRT 和 RVRT。它们通过时空注意力、clip 内并行建模、clip 间循环传播和 guided deformable attention 来恢复清晰视频，效果强但显存和部署成本较高。

最核心的一句话是：

工程上做视频去模糊，轻量快速选 NAFNet / ESTRNN，经典多帧选 EDVR，高质量离线选 RVRT / VRT，商业产品可以考虑 Topaz Themis 或 NVIDIA Maxine Deblur。

## 十八、工程上常用的压缩视频增强模型算法

“压缩视频增强”工程上一般不是单纯超分，而是专门处理 压缩伪影：块效应、振铃、蚊噪、边缘糊、纹理丢失、色带、时间闪烁等。它在业务里常见于低码率直播、短视频平台二压、监控视频、会议视频、老视频修复、转码后处理。

工程上常用方法可以分成 5 类：

传统 codec / FFmpeg 后处理
逐帧图像压缩伪影去除模型
多帧压缩视频质量增强模型
通用视频复原模型迁移到压缩视频增强
codec-aware / 码流感知增强模型
### 1. 传统 codec 后处理：Deblocking / SAO / ALF / FFmpeg deblock

这是工程里最基础、最稳的一类。视频编码本身就会产生块效应和量化误差，所以很多编码标准内部已经带有环路滤波。HEVC/H.265 标准中包含 deblocking filter 和 SAO，deblocking 主要缓解预测块、变换块边界的不连续，SAO 进一步修正像素偏差；VVC/H.266 还引入了 ALF、CC-ALF 等更强的环路滤波模块。

工程后处理里，FFmpeg 也提供 deblock 滤镜，官方文档说明它用于移除输入视频的 blocking artifacts，并支持 weak/strong、block size 等参数。

这一类的特点是：

方法	作用	优点	缺点
Deblocking	去块效应	快、稳定、低成本	对纹理恢复有限
SAO / ALF	修正编码误差	codec 内部集成	受编码器/标准限制
FFmpeg deblock	解码后处理	易部署、无训练	强度不好调，容易糊
Dering / sharpen	减少振铃或增强边缘	实时性好	可能放大噪声

这类方法适合实时转码、播放器后处理、低成本增强。但它们不能真正恢复丢失的细节，只能让伪影不那么明显。

### 2. 逐帧图像压缩伪影去除：AR-CNN、FBCNN、SwinIR

这一类把压缩视频拆成一帧一帧处理，本质是 图像 JPEG / 压缩伪影去除。流程通常是：

视频解码成帧
    ↓
每帧送入压缩伪影去除模型
    ↓
输出增强帧
    ↓
重新合成视频
2.1 AR-CNN

AR-CNN 是早期经典压缩伪影去除 CNN。论文指出有损压缩会带来 blocking artifacts、ringing effects 和 blurring，而传统方法要么去块后变糊，要么锐化后带来振铃；AR-CNN 用一个紧凑 CNN 来统一减弱这些压缩伪影。

它现在更多是学习和 baseline 价值，真实工程中通常不会直接用它做最终方案，但它是压缩伪影去除深度学习路线的起点。

2.2 FBCNN

FBCNN 是更工程化的 JPEG artifact removal 模型。它的特点是 blind JPEG artifacts removal，也就是不需要你准确知道 JPEG quality factor。它通过 decoupler module 预测可调质量因子，并通过 quality factor attention 控制“去伪影强度”和“细节保留”的权衡。

这对工程很重要，因为真实视频帧往往经历多次压缩，你很难知道真实 QP/QF。FBCNN 的思路适合做成用户可控参数：

强去伪影：画面更干净，但可能更平滑
弱去伪影：保留更多细节，但残留伪影更多
2.3 SwinIR

SwinIR 是基于 Swin Transformer 的通用图像复原模型，覆盖超分、去噪和 JPEG compression artifact reduction。官方说明 SwinIR 在 JPEG 压缩伪影去除任务上也取得了很强结果。

逐帧方案的优点是部署简单、延迟低、容易转 ONNX / TensorRT；缺点是没有显式时间一致性，可能出现帧间闪烁。对于直播、会议、短视频二压，如果实时性比极致质量更重要，逐帧模型仍然很常见。

### 3. 多帧压缩视频增强：MFQE、MFQE 2.0、STDF、RFDA

这一类是真正针对 compressed video enhancement / video compression artifact reduction 设计的模型。它们不只看当前帧，而是利用邻近帧的信息。

压缩视频有一个很重要的特点：不同帧质量不是均匀的。比如 I/P/B 帧、运动复杂度、码率分配不同，会导致某些帧质量更好，某些帧质量更差。MFQE 这类方法就是利用这个现象。

3.1 MFQE / MFQE 2.0

MFQE 全称是 Multi-Frame Quality Enhancement for Compressed Video。它的核心观察是：压缩视频存在明显的 frame-level quality fluctuation，高质量邻近帧可以帮助增强低质量帧。MFQE 不是只处理单帧，而是用邻近的高质量帧，也就是 PQF，来增强低质量非 PQF 帧。

MFQE 2.0 进一步提出用 BiLSTM 检测 Peak Quality Frames，然后用 MF-CNN 融合当前非 PQF 和最近的两个 PQF 来增强压缩视频。

它的逻辑可以写成：

压缩视频
    ↓
检测高质量帧 PQF
    ↓
选择当前低质量帧附近的 PQF
    ↓
运动补偿 / 特征融合
    ↓
增强当前帧

优点是思路非常适合压缩视频，因为压缩视频确实有质量波动。缺点是 PQF 检测和邻近参考帧选择会增加流程复杂度，而且在所有帧都被重度压缩时，高质量参考帧也不一定可靠。

3.2 STDF

STDF 全称是 Spatio-Temporal Deformable Fusion，是压缩视频质量增强里很经典的多帧方法。论文提出 STDF 用目标帧和邻近参考帧共同预测 deformable convolution 的 offset field，让卷积在时空维度上自适应采样，从而聚合邻近帧的互补信息。

它的核心思想是：

输入：当前压缩帧 + 邻近压缩帧
        ↓
STDF：时空可变形融合
        ↓
QE 网络：质量增强
        ↓
输出增强当前帧

相比显式光流，STDF 更像“隐式对齐”：

光流：先估计运动，再 warp
STDF：直接学习应该从邻近帧哪里采样特征

这对压缩视频很有用，因为压缩伪影会干扰光流估计，而 deformable fusion 可以在特征层面更灵活地对齐。

3.3 RFDA

RFDA 是 Recursive Fusion and Deformable Spatiotemporal Attention for Video Compression Artifact Reduction。官方代码说明它就是针对 video quality enhancement / video compression artifact reduction 任务，并且框架基于 STDF。

它可以理解为在 STDF 的基础上继续增强：

STDF：时空可变形融合
RFDA：递归融合 + 可变形时空注意力

如果你面试中想讲“压缩视频增强专用模型”，STDF 和 RFDA 比直接讲 Real-ESRGAN 更贴题，因为它们明确针对视频压缩伪影，且利用多帧信息。

### 4. 通用视频复原模型迁移：BasicVSR++、RealBasicVSR、VRT、RVRT

很多工程项目不会只训练一个“压缩伪影去除模型”，而是把压缩视频增强当作 视频复原任务，使用更通用的视频复原 backbone。

4.1 BasicVSR++

BasicVSR++ 原本是视频超分模型，但它在压缩视频增强任务上也表现很强。论文中专门报告了 compressed video enhancement 结果，并指出 BasicVSR++ 在 NTIRE 2021 compressed video enhancement challenge 的 top-ranking 方法上有明显优势；项目页也说明 BasicVSR++ 能泛化到 compressed video enhancement，并在 NTIRE 2021 的视频超分和压缩视频增强挑战中取得多个冠军/亚军结果。

它为什么适合压缩视频增强？

因为压缩视频增强本质上也需要：

跨帧对齐
长时序信息利用
局部细节恢复
抑制伪影传播

BasicVSR++ 的二阶网格传播和 flow-guided deformable alignment，可以从多帧中找回压缩丢失的细节，同时缓解单帧处理的闪烁问题。

适合：

高质量离线压缩视频增强；

短视频平台二压修复；

和超分、去噪、去模糊联合处理；

面试项目展示时序建模能力。

缺点是：推理和部署比逐帧模型复杂，DCN / 光流 / 长序列推理都需要工程处理。

4.2 RealBasicVSR

RealBasicVSR 面向真实世界视频超分，但它对压缩视频增强也很有启发。它指出真实视频退化复杂，长时序传播既能恢复细节，也可能把严重退化和伪影放大；因此它在 BasicVSR 前加入 image cleaning module，先清理输入的噪声和伪影，再做时序传播。

这对压缩视频非常关键。低码率视频中有大量块效应、蚊噪、振铃，如果直接用 recurrent propagation，模型可能会把这些伪影当成纹理传播到后续帧。

所以 RealBasicVSR 的工程思想是：

先清理压缩伪影
    ↓
再做多帧传播和细节恢复

这比“直接把压缩视频送进 BasicVSR”更稳。对于真实低码率视频，RealBasicVSR 的 pre-cleaning 思路很值得借鉴。

4.3 VRT / RVRT

VRT 是 Video Restoration Transformer，具备 parallel frame prediction 和 long-range temporal dependency modeling 能力；它的 TMSA 模块把视频分成 clips，通过 mutual attention 联合完成运动估计、特征对齐和特征融合。

RVRT 则是 Recurrent Video Restoration Transformer with Guided Deformable Attention，面向视频超分、去模糊、去噪等复原任务，强调在模型大小、测试显存和运行时间之间取得更好平衡。

对于压缩视频增强，它们的优势是：

能建模较长时序
能处理复杂运动
能同时做去噪、去伪影、去模糊、细节恢复

但工程上也有明显问题：

显存高
推理慢
长视频要切段
部署 ONNX / TensorRT 较难
真实低码率视频可能需要专门微调

所以 VRT / RVRT 更适合服务器离线增强，不太适合移动端实时压缩视频增强。

### 5. Codec-aware / 码流感知增强：更贴近工程的新方向

压缩视频和普通退化图像不同，它有很多 codec 信息可以利用，例如：

QP / QF
帧类型 I/P/B
运动矢量
残差
块划分
码率
参考帧关系

传统图像复原模型只看到 RGB 帧，不知道这些编码信息。Codec-aware 方法会把这些信息作为先验，辅助模型判断哪里压缩严重、哪里需要增强。

2025 年的 Plug-and-Play Versatile Compressed Video Enhancement 就提出了一个 codec-aware enhancement framework，复用 codec 信息，在不同压缩设置下自适应增强视频，同时避免引入明显计算瓶颈。

这类方法很贴近真实工程，因为线上视频系统天然能拿到码流信息。如果你做转码端增强、播放器端增强、云端视频质量修复，这类方法比单纯 RGB 后处理更有潜力。

可以理解为：

普通增强模型：
只看解码后的 RGB / YUV

codec-aware 模型：
RGB / YUV + QP + motion vector + residual + block info

优点：

更知道哪里被压缩坏了
可以针对 QP 自适应调节强度
更适合不同码率、不同编码器

缺点：

实现依赖解码器和码流解析
跨 codec 泛化较麻烦
工程集成比纯图像模型复杂
工程上怎么选模型
场景	推荐方案
实时播放器后处理	FFmpeg deblock / 轻量 CNN / NAFNet-lite
低延迟直播增强	逐帧 FBCNN / SwinIR-light / 轻量 U-Net
高质量离线压缩视频修复	BasicVSR++ / RVRT / VRT
专门做压缩伪影去除研究	MFQE 2.0 / STDF / RFDA
真实低码率短视频增强	RealBasicVSR 思路 + pre-cleaning
端侧部署	轻量 CNN、FBCNN-like、Mobile U-Net
云端转码后处理	codec-aware 模型 + 多帧增强
面试项目	STDF 或 BasicVSR++ + 逐帧 baseline 对比
推荐你重点掌握的 6 个模型/路线

如果你准备视频增强面试，压缩视频增强这块建议按这个顺序掌握：

1. FBCNN：逐帧盲压缩伪影去除

关键词：

blind JPEG artifact removal
quality factor prediction
强度可控
部署简单

适合回答“如果低延迟怎么办”。

2. MFQE 2.0：利用压缩视频质量波动

关键词：

PQF
quality fluctuation
BiLSTM detector
multi-frame enhancement

适合回答“压缩视频和普通视频复原有什么区别”。

3. STDF：压缩视频增强经典多帧模型

关键词：

spatio-temporal deformable fusion
不显式光流
多帧特征聚合
压缩视频专用

适合回答“多帧压缩伪影怎么去”。

4. BasicVSR++：通用视频复原强 backbone

关键词：

二阶网格传播
flow-guided deformable alignment
长时序信息
NTIRE compressed video enhancement

适合回答“如果追求高质量离线增强怎么办”。

5. RealBasicVSR：真实压缩退化的清理思路

关键词：

pre-cleaning
真实退化
防止伪影在传播中放大
detail-artifact tradeoff

适合回答“真实低码率视频为什么难”。

### 6. Codec-aware enhancement：工程化方向

关键词：

QP
motion vector
residual
block partition
codec information
adaptive enhancement

适合回答“如果你在视频平台或转码系统中落地，怎么进一步优化”。

一个典型工程 pipeline

实际做压缩视频增强项目，可以设计成这样：

输入压缩视频
    ↓
解码为 YUV / RGB 帧
    ↓
可选：读取 codec 信息
        QP、帧类型、运动矢量、残差、块划分
    ↓
轻量预清理
        去块效应、去蚊噪、去振铃
    ↓
多帧增强模型
        STDF / BasicVSR++ / RVRT
    ↓
可选：感知增强
        纹理恢复、轻量锐化、超分
    ↓
时间一致性检查
        防闪烁、防过增强
    ↓
重新编码输出

如果是你做面试 demo，我建议做两个版本：

Baseline：
FFmpeg deblock / FBCNN 逐帧增强

Advanced：
STDF 或 BasicVSR++ 多帧增强

然后展示：

原压缩视频
逐帧增强结果
多帧增强结果
局部放大对比
PSNR / SSIM / LPIPS / VMAF
运行速度
是否闪烁
面试里可以这样总结

压缩视频增强主要是解决低码率编码带来的块效应、振铃、蚊噪、模糊、细节丢失和时间闪烁。工程上最基础的是 codec 内部的 deblocking、SAO、ALF 以及 FFmpeg 这类传统后处理；低延迟场景常用逐帧压缩伪影去除模型，比如 AR-CNN、FBCNN、SwinIR；如果要真正利用视频信息，就会用 MFQE、STDF、RFDA 这类多帧压缩视频增强方法，它们利用质量波动、邻近帧参考和时空可变形融合来恢复当前帧。高质量离线场景则可以用 BasicVSR++、RealBasicVSR、VRT、RVRT 这类通用视频复原 backbone。更贴近平台工程的新方向是 codec-aware enhancement，把 QP、运动矢量、残差、块划分等码流信息输入模型，让增强强度随压缩程度自适应变化。

最核心的一句话是：

压缩视频增强的关键不是简单锐化，而是根据压缩伪影类型和时间一致性，在“去块/去噪/去振铃”和“保细节/防闪烁”之间做平衡；低延迟用逐帧模型，高质量用多帧视频模型，平台级落地最好结合 codec 信息。

## 十九、工程上常用的低照度视频增强模型算法

低照度视频增强在工程上不是单纯“把画面调亮”，而是一个组合任务：

低照度视频增强 = 提亮 + 去噪 + 去色偏 + 去模糊 + 保细节 + 保时间一致性

低照度场景最大的问题是：亮度低只是表象，真正难的是信噪比低。画面一提亮，暗部噪声、压缩块、彩噪、运动模糊、闪烁都会被一起放大。所以工程上常见的低照度视频增强方法，大致分成下面几类。

1. 传统 ISP / 图像增强方法

这类方法不是深度学习模型，但工程上非常常见，尤其在摄像头、手机、监控、车载相机里。

常见方法包括：

方法	作用	优点	缺点
Gamma 校正	提亮暗部	快、简单	容易过曝、噪声放大
直方图均衡 / CLAHE	增强局部对比度	无需训练	容易颜色失真、噪声增强
Retinex / MSRCR	分离光照和反射	适合非均匀光照	参数敏感，可能有光晕
时域降噪	利用多帧平均降噪	稳定、低成本	运动区域容易拖影
ISP 3A + 去噪	自动曝光、白平衡、降噪	产品中常用	依赖硬件和传感器

这类方法的工程优点是 快、稳定、可解释、容易部署。缺点是它们通常只能做基础增强，遇到极暗、强噪声、运动模糊、复杂光照时效果有限。

比如监控视频里经常会采用：

低照度输入
    ↓
时域降噪
    ↓
Gamma / Retinex 提亮
    ↓
锐化 / 对比度增强
    ↓
编码输出

但这种 pipeline 最大的问题是：提亮后噪声明显，且运动区域容易拖影。

2. 逐帧低照度图像增强模型

这是工程上最快落地的一类。它把视频拆成一帧一帧处理：

视频帧 1 → 图像低照度增强模型
视频帧 2 → 图像低照度增强模型
视频帧 3 → 图像低照度增强模型
...

优点是部署简单、速度快、模型成熟。缺点是没有显式时间一致性，容易出现 闪烁、亮度跳变、颜色跳变、纹理抖动。

2.1 Zero-DCE / Zero-DCE++

Zero-DCE 是工程上很常见的轻量低照度增强方法。它不是直接生成增强图，而是把低照度增强看成 曲线估计任务：网络预测一组像素级增强曲线，然后反复作用在输入图像上，实现亮度调整。Zero-DCE 的一个重要特点是 zero-reference，训练时不需要成对的低照度/正常光图像，而是用曝光、颜色、空间一致性等无参考损失约束增强结果。

它的流程可以理解为：

低照度图像
    ↓
DCE-Net 预测像素级增强曲线
    ↓
多次曲线映射
    ↓
增强图像

Zero-DCE++ 是更轻量版本，官方介绍其网络只有约 10K 参数，并强调在 GPU / CPU 上都具有很高推理速度。

工程上适合：

实时低照度增强；
移动端 / 嵌入式；
视频会议预处理；
作为视频增强 pipeline 的第一版 baseline。

缺点是：

逐帧处理视频容易闪烁；
强噪声场景下会把噪声一起提亮；
对极暗区域细节恢复有限；
容易过饱和或局部过曝。

一句话总结：

Zero-DCE 适合快速、轻量、无监督的低照度提亮，但它本质上是逐帧亮度映射，不是完整的视频增强模型。

2.2 RetinexNet / Retinex 类深度模型

Retinex 类方法基于一个经典假设：

图像 = 反射分量 × 光照分量

其中：

反射分量：物体本身颜色和纹理
光照分量：场景照明强弱

低照度增强的目标是：

保持反射分量
增强光照分量
抑制反射中的噪声

RetinexNet 这类方法通常包含：

Decomposition Network：分解反射和光照
Enhancement Network：增强光照
Denoising / Restoration：抑制噪声和伪影

Retinex 思路的优点是可解释性强，很适合回答面试问题：

低照度增强不是简单提亮，而是要区分“光照不足”和“物体真实反射”。

缺点是：

分解不准会导致颜色偏移；
暗部噪声会进入反射分量；
视频逐帧处理会产生时间闪烁。

工程上，Retinex 类方法适合做 解释性强的 baseline，但如果要真实视频落地，通常还需要配合视频去噪和时间一致性约束。

2.3 EnlightenGAN

EnlightenGAN 是无配对监督的低照度图像增强方法，官方实现说明其目标是 “Deep Light Enhancement without Paired Supervision”。

它适合真实场景，因为真实低照度数据很难获得严格配对的正常光 GT。它的优势是：

不需要成对数据
主观视觉效果较自然
适合真实低照度图像增强

但工程上用于视频时仍然有逐帧模型的问题：

每帧增强程度不同
    ↓
视频播放时亮度和颜色抖动

所以如果用 EnlightenGAN 做视频增强，最好额外加：

光流一致性损失
亮度平滑约束
时域滤波
多帧融合模块
2.4 MBLLEN

MBLLEN 是 BMVC 2018 的低照度图像/视频增强方法，核心是 Multi-Branch Low-Light Enhancement Network。官方项目页介绍它由特征提取模块、增强模块和融合模块组成，利用多分支结构从不同层次增强图像。

它的核心思想是：

浅层特征：颜色、边缘、局部纹理
中层特征：局部结构
深层特征：全局语义和光照
        ↓
多分支增强
        ↓
融合输出

工程上 MBLLEN 比传统 Retinex 更像一个完整 CNN 增强器。它可以处理图像，也可以逐帧处理视频。

缺点仍然是：

逐帧增强 → 时间一致性不足
低照度噪声 → 容易被增强
3. 真正的视频低照度增强模型

逐帧模型虽然容易落地，但视频增强的核心问题是 时间一致性。

低照度视频里常见问题包括：

帧间亮度跳变
暗部噪声闪烁
颜色忽冷忽暖
边缘和纹理抖动
运动区域拖影
局部区域过曝

所以视频模型通常会引入：

多帧输入
光流对齐
3D 卷积
循环传播
时序一致性损失
跨帧注意力
Retinex 视频分解
3.1 StableLLVE：让单帧增强模型学会时间一致性

StableLLVE 来自 CVPR 2021，论文题目是 Learning Temporal Consistency for Low Light Video Enhancement from Single Images。它的关键问题是：很多低照度增强数据只有静态图像，没有视频配对数据；单帧模型直接用于视频会产生严重闪烁。论文提出用静态图像训练时也能学习时间一致性，通过模拟运动和一致性约束，让模型增强视频时更稳定。

它的思想可以理解为：

训练时：
单张低照度图像
    ↓
模拟运动变换
    ↓
得到伪视频帧
    ↓
约束增强前后保持时间一致

测试时：
逐帧增强真实视频
    ↓
减少闪烁

这个方法很工程化，因为它回答了一个实际问题：

没有大量低照度视频配对数据，怎么训练一个视频稳定的增强模型？

它适合：

数据不足；
想把单帧增强模型稳定化；
需要较低部署复杂度；
不想引入很重的视频网络。

缺点是：

本质上仍偏逐帧增强；
对真实复杂运动、遮挡、极暗噪声处理有限；
不能充分利用多帧互补信息。
3.2 TCE-Net：3D + 2D 卷积的视频增强

TCE-Net 是 IJCV 2024 的低照度视频增强方法，官方介绍为 Temporally Consistent Enhancement of Low-Light Videos via Spatial-Temporal Compatible Learning。它构建了合成的低照度/正常光配对视频数据，并提出 TCE-Net，使用堆叠的 3D 卷积和 2D 卷积来利用视频中的时空线索。

它的结构思路可以理解为：

连续低照度视频帧
    ↓
3D 卷积：提取短时序运动和亮度变化
    ↓
2D 卷积：恢复每帧空间细节
    ↓
时间一致性约束
    ↓
增强视频

3D 卷积的作用是同时看：

高度 H
宽度 W
时间 T

所以它能直接学习：

相邻帧之间哪些结构稳定
哪些噪声是随机变化
哪些亮度变化应该保持平滑

优点：

比逐帧模型更稳定；
不依赖显式光流；
结构比 Transformer 视频模型更简单；
比较适合做工程视频增强 baseline。

缺点：

3D 卷积对长时序建模有限；
输入帧数增加会提升显存；
对大运动、遮挡、复杂动态场景不如带对齐或注意力机制的方法。
3.3 LAN / Dancing in the Dark：面向真实手机低照度视频

ICCV 2023 的 Dancing in the Dark 提出了一个面向通用低照度视频增强的 benchmark，并提出 Light Adjustable Network。论文贡献包括构建高质量配对低照度视频数据集，数据包含明显相机运动、严格空间对齐和多样场景内容；方法上基于 Retinex，迭代细化光照分量，并自适应调整光照。

它的工程价值在于：它更贴近真实手机低照度视频，而不是只在合成低照度数据上验证。

它的思路可以概括成：

低照度视频
    ↓
Retinex 分解
    ↓
迭代估计 illumination
    ↓
自适应调整亮度
    ↓
增强视频

这个方向适合：

手机拍摄夜景视频；
手持动态低光场景；
需要自然亮度调整；
避免过增强和过曝。
3.4 基于视频 Retinex 分解的新方法

低照度视频增强里，Retinex 仍然很重要。近年的一个趋势是：不再只做单帧 Retinex，而是做 视频级 Retinex 分解。

例如 2024/2025 一些工作会把视频分成：

view-independent component：物体本身稳定外观
view-dependent component：随视角和光照变化的成分

这类方法的目标是解决：

同一个物体在不同帧中应该保持一致
光照变化应该平滑
运动造成的视角变化要区别于亮度变化

相关工作指出，低照度视频增强不仅要恢复可见性和去噪，还要处理时空光照和外观一致性，这正是视频方法相对单帧方法的关键。

这类方法偏研究前沿，但工程启发很明显：

视频增强不能只在每帧上估计光照，而应该让同一场景/同一物体的光照和颜色在时间上连续。

4. RAW 域低照度视频增强 / 去噪

工程上，如果你能拿到 RAW 数据，低照度视频最好优先在 RAW 域处理。

原因是：

RAW 域：
噪声模型更接近传感器真实噪声
没有经过 ISP 锐化、压缩、颜色变换
更适合低照度恢复

sRGB 域：
已经经过 ISP、压缩和色彩处理
噪声和伪影更复杂
恢复更难
4.1 SID：Learning to See in the Dark

SID 是低照度 RAW 图像增强的经典工作。项目页指出，极暗成像时短曝光图像会有严重噪声，而长曝光会导致模糊且很多场景不可行；传统去噪、去模糊、增强方法在极暗视频率成像中效果有限。

SID 的核心思想是：

短曝光 RAW
    ↓
神经网络增强
    ↓
模拟长曝光正常亮度图像

虽然 SID 主要是图像，但它奠定了 RAW 低照度增强的工程思路：

与其在 sRGB 上强行提亮，不如直接从 RAW 传感器数据中恢复亮度和颜色。

4.2 RViDeNet / CRVD

RViDeNet 是 RAW 视频去噪/增强方向的重要方法。CRVD 数据集包含真实动态场景下的 noisy-clean RAW 视频对，ISO 覆盖较高范围，是 RAW 视频去噪的经典基准之一。

RAW 视频增强通常流程是：

Bayer RAW 视频
    ↓
pack 成多通道，例如 RGGB
    ↓
多帧时序去噪 / 增强
    ↓
融合
    ↓
ISP / demosaic / color correction
    ↓
输出 sRGB 视频

优点：

真实低照度去噪能力强；
保留更多原始信号；
比 sRGB 后处理更可控。

缺点：

需要 RAW 输入；
依赖相机传感器和 ISP；
不同设备泛化困难；
工程集成复杂。

适合：

手机夜景视频；
工业相机低照度；
安防低照度摄像头；
相机厂商 ISP pipeline；
RAW 视频挑战/研究。
4.3 Real-LLRVD

Real-LLRVD 关注真实低照度 RAW 视频去噪，其官方说明提到真实低照度视频中的噪声分布和运动模式非常复杂，并构建了包含复杂运动和高质量 GT 的 RAW 视频去噪数据集。

这个方向的工程意义是：

合成噪声和真实低照度 RAW 噪声差距很大，真实设备采集的数据集很重要。

如果你做真实项目，尤其是低光摄像头/手机相机，不要只拿合成噪声训练模型，最好采集真实 RAW pair 或做真实噪声建模。

4.4 BRVE：低成本 RAW 视频增强

BRVE 是 CVPR 2024 的 Binarized Low-light Raw Video Enhancement，官方介绍其目标是在低内存和低计算成本下实现低照度 RAW 视频增强，并提出易于二值化的时空 shift 操作和分布感知二值卷积。

这个方向对工程很有价值，因为很多低照度增强模型很重，端侧部署困难。BRVE 关注的是：

低算力
低内存
RAW 视频增强
二值神经网络

适合：

移动端；
嵌入式相机；
边缘设备；
实时 RAW 视频增强。

缺点是：

二值网络表达能力有限；
画质上限通常不如全精度大模型；
训练和量化设计更复杂。
5. 低照度视频增强 + 去噪 / 去模糊 / 超分联合模型

实际工程中，低照度视频往往同时存在：

暗
噪声大
运动模糊
压缩严重
分辨率低
颜色偏

所以很多项目不会只上“低照度增强模型”，而是用视频复原模型做联合增强。

常见组合包括：

低照度增强 + 视频去噪
低照度增强 + 视频去模糊
低照度增强 + 视频超分
低照度增强 + 压缩伪影去除

可选模型包括你前面问过的：

FastDVDnet / EMVD：低光视频去噪；
BasicVSR++：视频超分 / 通用视频复原；
RealBasicVSR：真实视频增强，先清理再时序传播；
VRT / RVRT：高质量视频复原 Transformer；
EDVR：多帧对齐和融合的视频复原经典模型。

工程上常见 pipeline 是：

低照度视频
    ↓
轻量去噪
    ↓
低照度增强 / illumination correction
    ↓
视频去模糊 / 超分 / 压缩增强
    ↓
时间一致性后处理

或者：

低照度视频
    ↓
一个统一视频复原模型
    ↓
同时输出亮度增强 + 去噪 + 细节恢复结果

第二种更优雅，但训练数据和模型设计更难。

6. 扩散模型 / 生成式低照度视频增强

最近几年也有扩散模型用于低照度增强，包括图像扩散和视频扩散。

优点：

生成先验强
暗部细节补全能力强
主观视觉质量好

缺点：

推理慢
显存高
容易生成假细节
视频时间一致性难
工程实时部署困难

例如有工作将低照度视频增强建模为条件扩散任务，并尝试在 wavelet domain 中降低显存和计算时间。

所以工程上目前扩散模型更适合：

离线高质量修复；
影视/老视频增强；
研究型项目；
作为 teacher 生成伪标签。

不太适合：

实时监控；
视频会议；
移动端；
对内容真实性要求很高的场景。

面试里可以这样说：

扩散模型适合作为高质量离线增强或教师模型，但工程实时落地仍然更偏向 Zero-DCE、TCE-Net、EMVD、RVRT 这类效率更可控的模型。

7. Event Camera 辅助的低照度视频增强

这是前沿方向，但工程上在自动驾驶、机器人、极暗动态场景里有潜力。

Event camera 的优势是：

高动态范围
低延迟
对运动敏感
极暗场景仍能捕捉边缘变化

低照度视频里普通相机帧可能非常暗、噪声很大，但 event 数据能提供运动边缘和结构线索。AAAI 2023 的事件引导低照度视频增强使用合成事件引导增强和恢复，包含事件合成增强、事件-图像融合、低照度增强三个阶段。

2024 以后也有真实事件引导低照度增强数据和方法，例如 EvLight++ 这类工作强调 event camera 在低照度下的高动态范围优势，并引入真实事件-视频数据。

适合：

自动驾驶夜间场景；
机器人视觉；
高速运动低照度场景；
科研项目。

缺点：

需要 event camera 硬件；
数据采集和标定复杂；
工程普及度低于普通 RGB 模型。
8. 商业 SDK / 产品方案

在视频会议、直播、摄像头增强中，很多公司不会自己训练完整低照度视频增强模型，而是使用商业 SDK。

11. 面试里可以这样总结

低照度视频增强工程上主要有四条路线。

第一条是传统 ISP / Retinex / Gamma / CLAHE 路线，优点是快、稳定、可解释，适合摄像头和监控预处理，但容易噪声放大和颜色失真。

第二条是逐帧深度增强路线，比如 Zero-DCE、Zero-DCE++、RetinexNet、EnlightenGAN、MBLLEN。它们部署简单，适合实时和移动端，但视频中容易出现闪烁和亮度跳变。

第三条是真正的视频低照度增强路线，比如 StableLLVE、TCE-Net、LAN 等，它们通过时间一致性约束、3D 卷积、多帧融合或视频 Retinex 分解来减少闪烁并利用时序信息。

第四条是 RAW / 高质量视频复原路线，比如 SID、RViDeNet、Real-LLRVD、BRVE、RVRT、VRT。RAW 域方法更适合手机相机和工业相机，高质量视频复原模型更适合服务器离线处理，但部署成本更高。

最核心的一句话是：

低照度视频增强不能只做“提亮”，工程上必须同时解决噪声放大、颜色偏移、运动模糊和时间闪烁；实时场景选 Zero-DCE++ / 轻量 Retinex，视频一致性选 StableLLVE / TCE-Net，高质量离线选 RAW 模型或 RVRT/VRT，真实产品最好结合 ISP 和时序去噪。

## 二十、工程上常用的视频插帧模型算法

视频插帧，工程里一般叫 VFI：Video Frame Interpolation，目标是在两帧之间生成中间帧：
输入：I0, I1输出：I0.5或者：24fps → 48fps / 60fps30fps → 60fps / 120fps普通视频 → 慢动作视频
工程上常用的视频插帧方法可以分成几类：传统光流插帧、RIFE 系列实时插帧、FILM 大运动插帧、GMFSS 动漫插帧、SoftSplat / DAIN / Super SloMo 等经典研究模型、商业 SDK / 软件方案。

### 1. 传统方法：帧复制、帧混合、光流运动补偿
最基础的插帧不是 AI，而是传统视频处理。
常见方式有三种：
1. Frame duplication：复制上一帧2. Frame blending：前后帧加权平均3. Motion-compensated interpolation：估计运动后插帧
FFmpeg 的 minterpolate 就是传统工程里常见的插帧滤镜。官方文档说明它可以把视频转换到指定帧率，并提供 dup、blend、mci 等模式，其中 mci 就是 motion compensated interpolation。
传统方法的优点是：
快稳定部署简单不需要深度学习模型
缺点是：
大运动容易扭曲遮挡区域容易鬼影复杂纹理容易糊人物手指、车轮、字幕边缘容易出错
所以现在高质量视频插帧通常会用深度学习模型。

### 2. RIFE / Practical-RIFE：工程上最常用的开源实时插帧
如果你问“工程上最常用、最容易跑、速度快”的视频插帧模型，优先记 RIFE。
RIFE 全名是 Real-Time Intermediate Flow Estimation。它的核心目标就是实时视频插帧。官方 ECCV2022-RIFE 仓库说明，它支持任意时间点插帧，并且在 2080Ti 上可以做到 720p 2× 插帧 30+ FPS。
它的基本思想是：
输入两帧 I0, I1        ↓估计中间时刻的运动流        ↓把前后两帧向中间时刻 warp        ↓融合 + refinement        ↓输出中间帧 It
RIFE 和传统光流方法的区别是：它不是先估计完整前后向光流再做复杂反转，而是直接估计中间流，减少了 flow reversal 带来的复杂度和误差。ECCV 论文说明 RIFE 更高效，并取得了更好的插帧性能。
工程上更常见的是 Practical-RIFE。它是 RIFE 的实用版本，长期维护了不同版本模型，比如 4.x 系列，并且项目说明中也提到部分版本适合用于 diffusion 生成视频后处理。
RIFE 适合：
30fps → 60fps24fps → 48fps / 60fps普通视频补帧AI 生成视频补帧实时或接近实时处理工程 Demo
优点：
速度快代码成熟资料多效果和速度平衡好支持任意时间插帧
缺点：
极大运动可能扭曲遮挡区域可能生成鬼影复杂重复纹理可能错位真实影视素材中人物手、头发、快速运动物体容易出错
一句话总结：

RIFE 是目前开源工程里最常用的视频插帧模型之一，优势是速度快、部署成熟、效果够好，非常适合做项目和面试 Demo。


### 3. FILM：更适合大运动、照片到慢动作
FILM 是 Google Research 的视频插帧方法，全名是 Frame Interpolation for Large Motion，ECCV 2022。官方项目说明，FILM 面向 large motion，可以把近重复照片生成看起来像视频拍摄的慢动作片段。
FILM 的特点是：
不依赖额外预训练光流或深度网络使用多尺度特征提取设计 scale-agnostic motion estimator对大运动更友好
官方 TensorFlow 实现说明，FILM 是一个 unified single-network approach，不使用额外预训练 optical flow 或 depth 网络，并且可以从 frame triplets 训练。
FILM 适合：
大运动插帧相邻照片生成慢动作摄影素材补帧对质量要求高、速度要求没那么极限的离线处理
和 RIFE 相比，可以这样理解：
RIFE：更偏实时、工程落地FILM：更偏大运动、高质量插帧
缺点是：工程生态、部署便利性和实时性通常不如 RIFE。

### 4. GMFSS / GMFSS-Fortuna：动漫插帧常见选择
如果是 动漫、动画、二次元视频补帧，工程社区里常见的是 GMFSS / GMFSS-Fortuna。
GMFSS 官方仓库说明它是 GMFlow based anime video frame interpolation，也就是基于 GMFlow 的动漫视频插帧方法。 GMFSS-Fortuna 项目也提供了直接运行视频插帧的命令，例如 --multi=2 做 2× 插帧。
动漫插帧和真实视频插帧不太一样。动漫有这些特点：
大面积纯色块清晰线稿低帧率抽帧运动不连续快速镜头切换夸张形变
真实视频插帧模型有时候会把动漫线条插坏，出现边缘抖动、线稿变形、糊边。GMFSS 这类方法更适合动画内容。
适合：
动漫 24fps → 60fps动画慢动作AI 动漫视频补帧ComfyUI / 视频生成后处理
缺点是：它不一定适合真实拍摄视频，而且不同版本模型差异较大，工程上需要测试素材匹配度。

### 5. SoftSplat：经典高质量插帧思想
Softmax Splatting / SoftSplat 是经典的视频插帧方法，核心是解决 forward warping 时的遮挡和冲突问题。官方说明 Softmax Splatting 是一种 differentiable forward warping 方法，用一个 translation-invariant importance metric 来处理多个源像素映射到同一个目标像素的情况。
你可以这样理解：
普通 warping 有两种：
Backward warping：目标帧每个像素去源帧采样优点：不会有空洞缺点：需要目标到源的反向对应Forward warping：源帧像素往目标帧投影优点：符合运动方向缺点：会有空洞和多像素冲突
SoftSplat 解决的是：
多个源像素投到同一个目标位置时，谁更重要？
它用 softmax 权重来决定融合优先级，因此对遮挡边界更合理。
SoftSplat 适合学习视频插帧原理，尤其是：
光流forward warping遮挡处理可微分 splatting
但工程上，现在如果只是要快速做补帧，通常会优先用 RIFE / Practical-RIFE，而不是直接用 SoftSplat。

### 6. DAIN、Super SloMo、SepConv、CAIN：经典模型，面试可讲
这些是视频插帧领域非常经典的方法，工程上现在不一定最常用，但面试和论文学习很有价值。
Super SloMo
Super SloMo 是早期很经典的慢动作插帧方法，核心是：
估计双向光流估计 visibility mapwarp 两帧到中间时刻融合生成中间帧
它的关键是 visibility map，用来判断中间帧中哪些区域应该更多来自前一帧，哪些应该更多来自后一帧。
DAIN
DAIN 是 Depth-Aware Video Frame Interpolation，核心是引入深度信息解决遮挡问题。直觉是：
前景物体深度更近遮挡发生时，前景应该覆盖背景
所以 DAIN 用深度帮助判断遮挡关系。它质量不错，但模型重，依赖深度估计，工程部署复杂。
SepConv
SepConv 用自适应可分离卷积进行插帧，不显式使用光流。它为每个像素预测局部卷积核，用周围像素加权生成中间帧。优点是结构思路清楚，缺点是大运动处理能力有限。
CAIN
CAIN 主要用 channel attention 做视频插帧，不显式依赖光流，结构相对简洁。它适合学习“无光流插帧”路线，但工程热度不如 RIFE。
这几个方法可以放在知识体系里：
Super SloMo：光流 + visibilityDAIN：光流 + 深度SepConv：自适应卷积CAIN：无光流 attentionSoftSplat：soft forward warpingRIFE：实时中间流估计FILM：大运动多尺度插帧

### 7. EMA-VFI、XVFI、IAM-VFI：较新的研究型方法
如果你想了解较新的研究方向，可以知道这些。
EMA-VFI 是 CVPR 2023 方法，官方仓库说明它利用 inter-frame attention 提取 motion 和 appearance 信息，并使用 CNN + Transformer 混合框架来平衡性能和效率。
XVFI 面向极端大运动插帧，官方仓库说明它提出了 X4K1000FPS 数据集，包含 4K、1000fps、高速大运动视频帧。 XVFI 论文摘要也说明 XVFI-Net 针对 4K 大运动视频插帧，使用递归多尺度共享结构。
IAM-VFI 是 ECCV 2024 方法，官方仓库标题说明其目标是使用 motion complexity map 来 “Interpolate Any Motion”。
这些方法更偏研究前沿。工程项目中如果追求稳定和资料成熟，还是优先 RIFE / Practical-RIFE / FILM / GMFSS。

### 8. 商业和 SDK 方案
工程产品里，很多团队不会自己训练插帧模型，而是用软件或 SDK。
NVIDIA Optical Flow SDK / FRUC
NVIDIA Optical Flow SDK 提供 Frame Rate Up Conversion 能力。官方文档说明，NvOFFRUC 可以用 optical flow vectors 插入新帧，把视频有效帧率翻倍，提升播放平滑度和视觉质量。 NVIDIA FRUC 文档也说明，其 API 接收两个连续帧，在中间生成插值帧，可用于游戏或视频内容的帧率提升。
适合：
NVIDIA GPU 环境实时播放增强视频播放器游戏录屏低延迟帧率提升
优点是硬件生态成熟，缺点是依赖 NVIDIA Optical Flow Engine 和 CUDA。
Topaz Video AI
Topaz Video AI 有专门的 Frame Interpolation 功能。官方文档说明，Frame Interpolation 是从已有帧合成新帧，用于更流畅运动或慢动作。 Topaz 的开发者文档还列出 Apollo、Chronos、Aion 等插帧模型，其中 Chronos 面向更具挑战的帧率转换和慢动作，Chronos Fast 则优先速度。
适合：
剪辑工作流影视素材慢动作老视频修复非程序员工具链
DaVinci Resolve Speed Warp
DaVinci Resolve 的 Speed Warp 使用 DaVinci Neural Engine 做高质量慢动作重建。官方手册说明 Speed Warp 在理想情况下可以比普通 optical flow 设置得到更高质量、更少伪影的慢动作效果。
适合：
影视剪辑商业后期慢动作制作

一个典型工程 pipeline
如果你要做一个视频插帧项目，可以这样设计：
输入视频    ↓ffmpeg 解码成帧    ↓镜头切换检测    ↓相邻帧送入插帧模型        RIFE / FILM / GMFSS    ↓生成中间帧    ↓按目标 fps 重排帧序列    ↓ffmpeg 合成视频    ↓保留原音频
这里有几个工程细节很重要。
第一，必须做镜头切换检测。
如果两个相邻帧其实是不同镜头，模型硬插帧会生成鬼影、混合画面。可以用直方图差异、SSIM、感知特征差异来判断 scene cut。
第二，目标 fps 要合理。
24→48、30→60 比较稳；如果直接 24→120，需要多次递归插帧，错误会累积。
第三，高分辨率要 tile 或降尺度处理。
4K 视频直接插帧显存压力大，工程里经常分块、半精度、分段处理。
第四，快速运动区域要检查伪影。
人物手指、球类、车轮、字幕、栅栏、头发、树叶是插帧模型最容易出错的地方。
第五，视频插帧不等于视频增强全部。
真实项目中常常组合：
去噪 / 去压缩伪影    ↓超分    ↓插帧    ↓锐化 / 色彩调整
顺序也要测试。有时先超分再插帧会更清晰但更慢；先插帧再超分会更快但细节可能弱。

面试里可以这样总结
视频插帧工程上主要有三条路线。
第一条是传统 motion interpolation，比如 FFmpeg 的 minterpolate，优点是简单、稳定、无需模型，缺点是大运动和遮挡场景容易鬼影。
第二条是深度学习开源模型，最常用的是 RIFE / Practical-RIFE。RIFE 直接估计中间流，速度快、支持任意时间插帧，很适合 30fps 到 60fps、AI 视频补帧和实时项目。FILM 更适合大运动和高质量离线插帧，GMFSS 更适合动漫补帧，SoftSplat、DAIN、Super SloMo 是理解光流、遮挡、深度和 splatting 的经典方法。
第三条是商业 SDK 和软件方案，比如 NVIDIA Optical Flow SDK 的 FRUC、Topaz Video AI 的 Apollo / Chronos / Aion、DaVinci Resolve 的 Speed Warp。它们工程成熟，适合产品和剪辑工作流，但模型细节不可控。
最核心的一句话是：
工程上做视频插帧，实时和开源优先 RIFE / Practical-RIFE，动漫优先 GMFSS，大运动和高质量离线可以考虑 FILM / Topaz，平台级实时可以用 NVIDIA Optical Flow SDK；真正落地时一定要处理镜头切换、高速运动伪影、高分辨率显存和音视频同步。
